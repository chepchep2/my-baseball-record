# Baseball Record V1 Design

## Goal

개인 선수 전용 모바일 웹 기록 관리 서비스로서의 Baseball Record v1을 설계한다.

이 문서는 PRD가 고정한 제품 범위를 바탕으로,
v1이 어떤 정보구조와 데이터 구조를 갖고 어떤 방식으로 기록 확인, 경기 관리, 기록 입력을 연결해야 하는지 정의한다.

## Design Position

v1의 중심 가치는 `빠른 입력`이 아니라 `기록 확인과 누적 관리`다.

사용자는 여러 출처에 흩어진 자신의 기록을 이 앱에 직접 입력하고,
앱은 이를 시즌/통산 기준으로 누적 계산해 보여준다.
여기에 더해 사용자는 입력한 경기들을 날짜 기준으로 다시 찾아 확인하고 수정하거나 삭제할 수 있어야 한다.

즉 설계 우선순위는 아래와 같다.

1. 기록이 한곳에 계속 쌓이고 관리된다는 감각
2. 이번 시즌 핵심 지표를 명확히 보는 경험
3. 날짜 기준으로 입력한 경기를 다시 관리할 수 있는 경험
4. 경기 후 기록을 실제로 계속 추가할 수 있는 입력 흐름

## Product Boundaries

### Product Identity

v1은 아래 제품으로 정의한다.

- 개인 선수 전용
- 모바일 웹 우선
- 기록 확인 중심
- 경기 입력 및 경기 관리 지원

### User Boundary

- 계정 1개는 선수 프로필 1개와 연결된다.
- 사용자는 자신의 기록만 관리한다.
- 다른 선수 기록을 대신 관리하지 않는다.
- 하나의 실제 경기를 여러 사용자가 공유하는 협업 모델은 v1에 넣지 않는다.

### Scope Boundary

v1은 팀 운영 도구가 아니다.
또한 리그 관리 도구도 아니다.

따라서 아래 항목은 설계 대상에서 제외한다.

- 팀 로스터 관리
- 팀 공동 입력
- 다중 선수 프로필 관리
- 타인 기록 대리 관리
- 외부 기록 자동 연동
- 타석별 상세 로그
- 이닝별 상세 로그

## Mobile Web Design Principles

### Principle 1: Record View First

기본 홈은 `홈 화면`이다.
기록이 하나도 없어도 홈은 바뀌지 않는다.

즉 v1의 첫 화면은 아래 역할을 동시에 가져야 한다.

- 이번 시즌 기록 구조를 보여준다.
- 기록이 쌓일 자리라는 감각을 준다.
- 다음 행동으로 `생성` 또는 `기록`을 유도한다.

### Principle 2: Management Must Stay Practical

기록 확인만 되고 관리가 안 되는 구조는 v1에서 충분하지 않다.
사용자는 입력한 경기를 날짜 기준으로 다시 찾고, 필요하면 수정/삭제할 수 있어야 한다.

모바일 사용성은 아래 방식으로 확보한다.

- 하단 탭바를 통한 전역 복귀
- 캘린더 기반 경기 관리
- 개별 경기 상세 진입
- 수정 시 기존 입력 화면 재사용
- 삭제 시 확인 모달

### Principle 3: Clarity Beats Speed

판단이 갈릴 때는 입력 속도보다 기록 관리의 명확성을 우선한다.

즉 첫 화면의 정보 밀도는 입력 유도를 위해 제품 정체성을 해치지 않는 수준으로 설계하고,
입력 화면은 짧아 보이게 만드는 것보다 `실수 없이 다시 볼 수 있는 기록을 남기는 것`을 우선한다.

### Principle 4: Mobile Constraints Are Real

문서는 아래 상황을 기본 전제로 가진다.

- 스마트폰 세로 화면
- 한 손 사용 가능성
- 짧은 집중 시간
- 경기 직후 입력
- 경기 중 점진 입력
- 나중에 다시 정리 입력
- 저장 실패 가능성
- 입력 중 이탈 가능성

## Core User Flow

1. 사용자가 구글 로그인으로 인증을 완료한다.
2. 홈 화면으로 진입한다.
3. 사용자는 이번 시즌 핵심 지표를 먼저 본다.
4. 더 많은 누적 지표가 필요하면 기록 탭으로 이동한다.
5. 새 경기 기록이 생기면 생성 탭으로 이동한다.
6. 날짜 기준으로 입력한 경기를 관리하려면 경기 탭으로 이동한다.
7. 경기 탭에서 날짜를 선택하고 그 날짜의 경기 목록을 본다.
8. 경기 카드를 눌러 개별 경기 상세 화면으로 이동한다.
9. 더보기 메뉴에서 수정 또는 삭제를 선택한다.
10. 수정은 입력 화면 재사용으로 처리하고, 삭제는 확인 모달 뒤 실행한다.

## Scenario Coverage

같은 정보구조는 아래 4가지 대표 시나리오를 모두 지원해야 한다.

- 시즌 중간 점검
  - 홈에서 현재 시즌 핵심 성적을 확인한다.
  - 필요하면 기록 탭으로 들어가 더 깊게 본다.
- 경기 직후 입력
  - 생성 탭으로 이동해 새 경기를 남긴다.
- 경기 중 점진 입력
  - 생성 탭에서 경기 정보를 먼저 만들고 기록 입력 단계에서 경기 중간중간 값을 이어서 쌓는다.
- 시즌 마감 정리
  - 경기 탭에서 날짜별로 누락 경기를 확인하고 정리한다.
- 잘못 입력한 경기 수정
  - 경기 탭에서 특정 날짜의 경기를 찾아 개별 경기 상세로 들어간 뒤 수정한다.

## Information Architecture

### Primary Structure

v1은 하단 탭바 중심 구조를 사용한다.

프론트엔드 구현 기술은 Next.js를 기준으로 하되,
이 문서의 정보구조와 화면 책임은 특정 프레임워크의 파일 구조보다 우선한다.

핵심 구조는 아래와 같다.

- 인증 화면
- 홈 화면
- 기록 화면
- 생성 화면
- 경기 화면
- 내 정보 화면
- 개별 경기 상세 화면
- 삭제 확인 모달

하단 탭 순서는 아래로 고정한다.

- 홈
- 기록
- 생성
- 경기
- 내 정보

### Screen Roles

- 홈
  - 현재 시즌 핵심 요약만 빠르게 본다.
- 기록
  - 누적 기록 상세를 본다.
- 생성
  - 새 경기 입력을 시작한다.
- 경기
  - 캘린더 기반으로 날짜별 경기를 관리한다.
- 내 정보
  - 계정 정보와 로그아웃을 제공한다.
- 개별 경기 상세
  - 저장된 경기 1건의 입력값을 읽기 전용으로 보여준다.
  - 타자/투수는 화면 내 전환으로 나눠서 본다.

### Detail Screen Axes

기록 화면은 저장된 개별 경기 상세 화면이 아니라,
시즌/통산 누적 기록을 더 많이 보여주는 화면이다.

- 시간 축: `시즌 / 통산 / 특정 시즌`
- 기록 축: `타자 / 투수`
- 경기 필터: `전체 / 리그 / 비공식 경기`

### Game Management Structure

경기 화면은 아래 구조를 갖는다.

- 월간 캘린더가 먼저 보인다.
- 기본 진입 시 오늘 날짜를 자동 선택한다.
- 날짜 셀에는 경기 수를 표시한다.
  - `1`, `2`, `+3`
- 캘린더 아래에는 선택한 날짜의 경기만 카드형 목록으로 표시한다.
- 경기 카드에는 `날짜, 경기 유형, 참여 형태 라벨, 상대 팀`을 표시한다.
- 카드를 누르면 개별 경기 상세 화면으로 이동한다.

## Authentication Design

v1 인증은 `구글 로그인 + 앱 내부 access token / refresh token 기반 세션`으로 설계한다.

### Included

- 구글 로그인
- 로그아웃
- 토큰 재발급

### Ownership Rule

모든 경기와 기록 데이터는 로그인한 사용자 개인 소유로 분리 관리한다.
즉 데이터 조회와 저장은 항상 현재 로그인한 사용자 기준으로 동작한다.

### Logout Rule

로그아웃은 단순 클라이언트 토큰 제거가 아니라 refresh token 무효화를 포함한다.
위치는 `내 정보` 화면으로만 고정한다.

### Google Login Direction

- 사용자는 구글 계정으로 로그인한다.
- 구글 인증 성공 후 앱은 자체 세션을 위한 토큰을 발급한다.
- v1은 이메일/비밀번호 회원가입과 로그인을 지원하지 않는다.
- Google 계정 1개는 앱 계정 1개와 연결된다.
- 서로 다른 Google 계정은 서로 다른 앱 계정으로 취급한다.
- v1은 계정 연결과 계정 병합을 지원하지 않는다.

즉 별도의 다중 프로필 계층을 도입하지 않고,
한 사용자가 자신의 기록을 직접 관리하는 구조로 간다.

### Game

`Game`은 사용자의 개인 경기 기록 단위다.

#### Fields

- 날짜
- 시즌/연도

  - 필요 시 사용자가 생성 시점에 수정 가능
- 경기 유형
  - `LEAGUE`
  - `NON_OFFICIAL`
- 소속 팀
- 상대 팀
- 메모
- participationType
  - `BATTER`
  - `PITCHER`
  - `BOTH`

### Batter Record

- 3루타

#### Additional Input

- 볼넷

- 사구
- 타점
- 득점

- 도루자
- 희생타

#### Calculated Values

- 타율

- OPS

- 홀드

- WHIP
- 피안타율
- 탈삼진율

## Input Design

### Input Unit

v1의 입력 단위는 `경기 단위 요약 입력`이다.
타석별 로그, 이닝별 로그, pitch-by-pitch 입력은 제외한다.

### Create Flow

1. 경기 정보 입력
2. 기록 입력

기록 입력 단계 안에서는 타자 기록과 투수 기록을 필요한 만큼 입력한다.

### Draft Policy

- 생성 화면과 수정 화면 모두 임시 저장을 지원한다.
- 입력값이 바뀔 때마다 localStorage에 임시 저장한다.
- 생성 draft key는 `draft:create:{userId}`를 사용한다.
- 수정 draft key는 `draft:edit:{userId}:{gameId}`를 사용한다.
- 같은 세션 안에서 다시 들어오면 자동 복구한다.
- 브라우저 재진입 후 생성/수정 화면에 들어오면 복구 확인 모달을 띄운다.
- `예`를 누르면 복구하고, `아니오`를 누르면 임시 저장을 삭제한다.
- 최종 저장이 완료되면 임시 저장은 삭제한다.
- draft TTL은 7일로 둔다.
- 경기 중 점진 입력은 localStorage 임시저장만 사용하고 서버에는 최종 저장 시점에만 전송한다.

### Edit Flow

- 수정은 생성 화면을 재사용한다.
- 기존 입력값을 미리 채운다.
- `날짜`와 `경기 유형`은 읽기 전용으로 둔다.
- `시즌/연도`도 읽기 전용으로 둔다.
- 저장 완료 후 개별 경기 상세 화면으로 돌아간다.

### Input State Rules

- 타자만 입력 가능
- 투수만 입력 가능
- 둘 다 입력 가능
- 단계 전환 시 값 유지
- 타자/투수 탭 전환 시 값 유지
- 화면 이탈 시 경고
- 생성/수정 화면 모두 임시 저장과 복구를 지원

## Integrated Record Design

### Home Behavior

홈 화면은 v1의 기본 홈이다.

데이터가 없어도 아래 구조를 유지한다.

- 화면 제목
- 이번 시즌 기준 컨텍스트
- 핵심 지표 요약

### Empty State

빈 상태는 설명 화면으로 대체하지 않는다.
0 지표 기반 기록 구조를 먼저 보여준다.

### Home Summary Metrics

#### Batter

- 경기수
- 타수
- 총안타
- 타율
- OPS

#### Pitcher

- 경기수
- 이닝
- ERA
- WHIP
- 삼진
- 승

## Stats Display Rules

- 홈의 요약 지표와 기록 화면의 상세 지표를 구분한다.
- 모바일 첫 화면은 요약 지표를 우선한다.
- 상세 지표는 기록 화면에서 충분히 확인할 수 있어야 한다.
- 기록이 없어도 수치 구조는 유지한다.
- 타자 요약/대표 지표는 `경기수, 타수, 총안타, 타율, OPS`로 고정한다.
- 투수 요약/대표 지표는 `경기수, 이닝, ERA, WHIP, 삼진, 승`으로 고정한다.
- 타율과 OPS는 소수 셋째 자리까지 표시한다.
- ERA와 WHIP는 소수 둘째 자리까지 표시한다.
- 0분모 비율 지표는 v1에서 `0.000` 또는 `0.00`으로 표기한다.
- 투수 표시는 `0.0 / 0.1 / 0.2` 형식을 사용한다.

## Non-happy-path States

문서와 구현은 정상 흐름만 다루지 않는다.
아래 상태를 반드시 설계 대상에 포함한다.

- 빈 기록 상태
- 구글 로그인 실패 상태
- 구글 로그인 취소 상태
- 인증 만료 상태
- 저장 중 상태
- 저장 실패 상태
- 입력 중 이탈 시 확인 상태
- 삭제 확인 모달

- 타자/투수 경기 요약 기록 입력
- 한 경기에서 타자/투수 기록 동시 입력
- 시즌/통산 자동 누적 계산
- 홈 화면
- 기록 화면
- 생성 화면
- 경기 화면
- 내 정보 화면
- 하단 탭바
- 날짜 기반 시즌 자동 설정 및 수동 수정
- 빈 기록 화면 제공
- 모바일 웹 기준 입력 상태와 비정상 상태 처리

### Excluded

- 팀 생성
- 선수 등록을 통한 로스터 운영
- 다중 선수 프로필 관리
- 타인 기록 대리 관리
- 게임원/외부 사이트 자동 연동
- 타석별 상세 로그 입력
- 이닝별 상세 로그 입력
