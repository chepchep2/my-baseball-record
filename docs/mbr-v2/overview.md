# My Baseball Record v2 Overview

## 1. 문서 목적

이 문서는 My Baseball Record v2의 상위 방향을 정리한다.

다음 질문에 답하는 기준 문서다.

- v1에서 무엇을 유지하는가
- v2에서 무엇이 달라지는가
- v2의 핵심 사용자 흐름은 무엇인가
- v2 문서는 어디서부터 읽어야 하는가

## 2. v1 문서와의 관계

- `docs/milestone-1/`은 My Baseball Record v1 문서 세트로 그대로 보관한다.
- v2 내용은 `docs/mbr-v2/`에서 별도 문서 세트로 관리한다.
- v1 문서를 수정해 덮어쓰지 않는다.
- v2 문서는 v1과 같은 점을 다시 요약하고, 달라지는 점은 별도로 명시한다.

## 3. v1에서 유지하는 것

v2에서도 아래 원칙은 유지한다.

- 모바일에서 빠르게 기록을 남기는 제품 성격
- 타자 기록 중심 구조
- 기록 직후 홈에서 누적 결과를 바로 확인하는 흐름
- 과도한 입력을 피하는 제품 철학
- 카카오 로그인과 기본 인증 구조

즉 v2는 전혀 다른 제품이 아니라, v1의 핵심 가치를 유지한 확장 버전이다.

## 4. v2에서 달라지는 것

v1은 `내 개인 기록 1건을 빠르게 남기는 흐름`이 중심이었다.

v2는 그 위에 아래 개념을 추가한다.

- 기록 입력 전에 먼저 `같은 경기`를 찾거나 만들기
- 여러 사용자가 하나의 경기를 공유하기
- 경기 화면에서 같은 경기의 기록을 함께 보기
- 생성자 또는 기록 참여자가 다른 사람 기록을 인증하기

즉 v2의 핵심 변화는 `개인 기록 중심`에서 `공용 경기 + 개인 기록` 구조로 확장되는 것이다.

## 5. v2의 핵심 사용자 흐름

1. 사용자가 `+`로 진입한다.
2. 날짜, 시간, 지역을 입력한다.
3. 같은 날짜, 비슷한 시간대, 같은 구/군의 기존 경기 후보를 먼저 본다.
4. 기존 경기를 선택하거나 새 경기를 만든다.
5. 먼저 경기 화면으로 이동한다.
6. 경기 화면에서 현재 기록 목록을 보고 `내 기록 입력하기`로 들어간다.
7. 기록을 남긴 사용자는 그 경기의 참여자로 본다.
8. 생성자 또는 기록 참여자는 다른 사람 기록을 인증할 수 있다.

## 6. 데이터 구조의 방향

v2는 기존 데이터를 깨지 않게 점진 전환한다.

핵심 방향은 다음과 같다.

- `game_record`는 공용 경기 상위 엔티티로 확장한다.
- `batter_record`는 한 경기 안의 사용자별 타자 기록으로 확장한다.
- `stadium`은 구장 추천과 유사 이름 비교를 위한 기준 데이터로 둔다.
- 인증은 별도 verification 테이블로 관리한다.

## 7. v2의 1차 범위

포함:

- 경기 생성
- 기존 경기 후보 탐색
- 경기 상세 화면
- 사용자별 타자 기록 연결
- 기록 인증 표시
- 기존 데이터 호환

제외:

- 투수 기록
- 알림
- 운영자 정리 도구
- 인증 인원 수 노출
- 참여 승인
