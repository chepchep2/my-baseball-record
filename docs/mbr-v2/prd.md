# My Baseball Record v2 PRD

## 1. Product Summary

My Baseball Record v2는 사회인 야구 선수가 경기 후 자신의 타자 기록을 빠르게 남기는 v1의 성격을 유지하면서,
이제는 `같은 경기`를 먼저 찾거나 만들고 그 안에서 여러 사용자가 각자 기록을 남길 수 있게 하는 버전이다.

v2의 핵심은 단순히 입력 화면을 늘리는 것이 아니다.
경기라는 공용 단위를 만들고, 그 위에 개인 기록과 기록 인증을 연결하는 것이다.

## 2. Problem

현재 v1은 개인 기록 입력에는 강점이 있지만, 아래 문제를 해결하지 못한다.

- 같은 경기에서 여러 사용자가 기록을 남겨도 서로 연결되지 않는다.
- 경기 자체를 먼저 등록하고 다른 사람이 합류하는 흐름이 없다.
- 기록 신뢰도를 보여줄 인증 구조가 없다.
- 같은 경기인데 시간/구장 표기 차이로 쉽게 흩어진다.

즉 사용자는 빠르게 기록은 남길 수 있지만, `같이 한 경기`와 `기록 신뢰도`는 표현할 수 없다.

## 3. Product Goal

v2의 목표는 다음 두 가지다.

- 사용자가 경기 단위로 모일 수 있게 한다.
- 그 경기 안에서 남긴 기록에 최소 수준의 신뢰도 표시를 붙일 수 있게 한다.

즉 v2는 `빠른 개인 기록 입력`에서 `공용 경기 기반 기록 관리`로 제품 목적을 확장한다.

## 4. Success Metric

핵심 성공 지표 초안:

- 경기 생성 후 2명 이상이 같은 경기에서 기록을 남긴 비율
- 경기 화면에서 기록 인증이 1건 이상 발생한 비율

보조 지표:

- 경기 생성 후 첫 추가 참여까지 걸린 시간
- 기존 경기 후보 선택률
- 새 경기 생성률
- 인증 기록 비율

## 5. Target User

### Primary User

- 사회인 야구를 직접 하는 개인 선수
- 경기 후 기록을 남기고 싶은 사용자
- 공식 기록이 불완전한 경기에서도 스스로 기록을 관리하고 싶은 사용자
- 같은 경기의 다른 사용자와 기록을 연결하고 싶은 사용자

### Secondary User

- 경기 공지를 먼저 알고 있어서 경기를 먼저 등록하는 사용자
- 기록 정확도와 신뢰도에 관심이 많은 사용자

### Excluded User

- 리그 운영자
- 팀 운영 전용 사용자
- 투수 기록 중심 사용자
- 알림/일정 관리가 우선인 사용자

## 6. Scope

### In Scope

- 경기 생성
- 기존 경기 후보 탐색
- 지역/구장 선택
- 새 경기 생성
- 경기 상세 화면
- 사용자별 타자 기록 연결
- 기록 인증 표시
- 기존 데이터 호환

### Out of Scope

- 투수 기록
- 기록 인증 수 표시
- 인증 등급/가중치
- 참여 승인
- 일정 알림
- 운영자 수동 정리

## 7. Product Principles

### 1. Keep Fast Recording

v2가 경기 개념을 추가하더라도 기록 입력의 부담은 커지지 않아야 한다.
여전히 사용자는 짧은 시간 안에 자기 기록을 남길 수 있어야 한다.

### 2. 경기 먼저, 기록은 그 안에서

기록은 이제 공용 경기 안에 연결된다.
즉 개인 기록보다 먼저 경기 단위를 식별하는 흐름이 필요하다.

### 3. No Forced Operations Burden

운영자가 지역/구장 중복을 사후 정리해야 하는 구조는 1차에서 피한다.
대신 입력 시점의 추천과 유사 이름 경고로 데이터 품질을 최대한 높인다.

### 4. Backward Compatibility First

기존 사용자 기록과 홈/통계 경험은 깨지면 안 된다.
v2 구조는 기존 데이터를 유지한 상태에서 점진적으로 도입한다.

## 8. Main Experience

### Existing Game First

- 사용자는 날짜, 시간, 지역을 정한 뒤 먼저 기존 경기 후보를 본다.
- 후보가 있으면 기존 경기에 들어간다.
- 후보가 없으면 새 경기를 만든다.

### Game Screen First

- 경기 생성 또는 기존 경기 선택 후에는 바로 기록 입력으로 가지 않는다.
- 먼저 경기 화면으로 이동한다.
- 사용자는 경기 화면에서 현재 기록 목록을 보고 `내 기록 입력하기`로 들어간다.

### Record Participation Rule

- 기록을 실제로 남긴 사용자만 그 경기의 참여자로 본다.
- 경기만 만들고 기록을 남기지 않으면 최종 참여자로 보지 않는다.

### Verification Rule

- 생성자 또는 기록 참여자는 다른 사람 기록을 인증할 수 있다.
- 같은 사람이 같은 기록을 두 번 인증할 수는 없다.
- 1명이라도 인증하면 `인증 기록`으로 표시한다.

## 9. Input Model

### User Input Fields

v2에서도 사용자가 직접 입력하는 타자 기록 값은 아래 6개를 유지한다.

- 타석
- 사사구
- 1루타
- 2루타
- 3루타
- 홈런

### Game Identification Input

v2에서는 경기 식별 입력이 먼저 온다.

- 날짜
- 시간
- 시/도
- 구/군
- 구장

### Candidate Matching Rule

- 같은 날짜
- 입력 시간 기준 `±30분`
- 같은 `구/군` 우선
- 필요 시 `더 보기`로 범위 확장

### Stadium Input Rule

- 지역별 기존 구장 추천을 먼저 보여준다.
- 없으면 직접 입력할 수 있다.
- 유사 이름이 있으면 `기존 구장 선택 / 새 구장 추가`를 명시적으로 선택하게 한다.

## 10. Main Screen

홈 화면의 역할은 v1과 크게 다르지 않다.

- 시즌/통산 전환
- 핵심 지표 요약
- 최근 기록 리스트
- `+` 진입

다만 v2에서는 `+`가 더 이상 곧바로 개인 기록 입력으로 이어지지 않고,
`경기 생성/탐색`의 시작점이 된다.

## 11. Data Direction

### Shared Game

- `game_record`는 공용 경기 상위 엔티티로 확장한다.

### Personal Batter Record

- `batter_record`는 그 경기 안에서 사용자별 타자 기록으로 확장한다.
- 한 경기에는 여러 `batter_record`가 달릴 수 있다.
- 한 사용자는 한 경기에서 타자 기록 1개만 가진다.

### Verification

- 인증은 사용자별 기록 단위에 붙는다.
- 1차에서는 인증 수를 노출하지 않고, 인증 여부만 노출한다.

## 12. Migration Principle

- 기존 `game_record`, `batter_record`는 유지한다.
- 기존 홈/통계 데이터는 계속 보이게 한다.
- 새 구조는 점진적으로 도입한다.
- 읽기 호환성을 먼저 확보한 뒤 쓰기 구조를 확장한다.
