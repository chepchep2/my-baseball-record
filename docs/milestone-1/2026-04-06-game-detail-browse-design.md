# 기록 상세 및 전체 경기 탐색 화면 설계

## 1. 문서 목적

이 문서는 현재 실제 사용 중인 흐름을 기준으로
기록 상세 화면과 전체 경기 탐색 흐름을 정의하기 위한 설계 문서이다.

현재 실사용 기준 핵심 화면은 아래와 같다.

- `/auth`
- `/home`
- `/games/new`

이번 설계의 목표는 `/home`의 최근 경기 3개 외의 경기들도
사용자가 자연스럽게 탐색하고 상세 기록을 볼 수 있게 만드는 것이다.

## 2. 현재 문제

현재 홈 화면에는 `최근 경기 기록 리스트`가 있고 최근 경기 3개가 노출된다.
이 최근 경기 카드를 클릭하면 상세 기록 보기 화면으로 연결하는 방향은 자연스럽다.

하지만 이 구조만 두면 아래 문제가 생긴다.

- 최근 경기 3개 외의 기록은 어디서 상세로 봐야 하는지가 애매하다.
- 사용자가 "3월쯤 한 경기"처럼 대략적인 기억만 있을 때 진입 경로가 없다.
- 앞으로 수정/삭제 기능을 붙일 때 개별 경기 기준 진입 화면이 부족하다.

## 3. 목표와 비목표

### 목표

- 홈 화면의 최근 경기 카드에서 바로 상세 기록 보기로 들어갈 수 있어야 한다.
- 최근 경기 외의 모든 경기 기록을 모아 보는 별도 화면이 있어야 한다.
- 전체 경기 목록에서 원하는 경기를 찾은 뒤 상세 기록 보기로 들어갈 수 있어야 한다.
- 상세 기록 보기 화면은 현재 입력 화면을 최대한 재사용하되 읽기 전용 상태로 시작해야 한다.
- 수정은 기록 상세 화면에서 역할별로 분리해야 한다.
- 날짜/시간 수정은 별도 날짜/시간 수정 화면에서 처리해야 한다.
- 기록값 수정은 상단 `수정` 버튼으로 기록값 수정 화면에 진입해야 한다.
- 삭제는 기록 상세 화면에서 가능해야 한다.

### 비목표

- 이번 설계에서 캘린더 탐색 UI는 우선순위에서 제외한다.
- 이번 설계에서 투수 기록 입력은 포함하지 않는다.
- 이번 설계에서 새로운 복잡한 정보 구조를 추가하지 않는다.

## 4. 검토한 접근안

### 접근안 A. 홈 최근 경기 카드만 상세 진입점으로 사용

- 장점: 구현이 가장 단순하다.
- 단점: 최근 3개 외 경기의 상세 진입 경로가 없다.

### 접근안 B. 더보기 -> 전체 경기 목록 -> 카드 클릭 -> 별도 상세 화면 -> 수정 버튼으로 수정 화면 이동

- 장점: 역할 분리가 명확하다.
- 단점: 상세 확인 후 수정하려면 화면 이동이 한 번 더 필요하다.
- 단점: 현재 범위와 데이터 밀도 기준으로는 흐름이 길다.

### 접근안 C. 더보기 -> 전체 경기 목록 -> 카드 클릭 -> 상세 화면 -> 일시 수정/기록값 수정 분리

- 장점: 조회와 수정의 균형이 좋다.
- 장점: 현재 입력 화면을 재사용하기 쉽다.
- 장점: 날짜/시간만 고치고 싶을 때 기록값 단계까지 갈 필요가 없다.
- 장점: 기록값만 고치고 싶을 때 날짜/시간 단계까지 갈 필요가 없다.
- 장점: 기록값 수정 화면은 Entry Step 2 UI를 그대로 재사용할 수 있다.
- 장점: 날짜/시간은 달력과 시간 선택 UI가 크기 때문에 별도 화면으로 분리할 수 있다.
- 장점: 상세 화면의 존재 이유가 분명해진다.

### 추천안

접근안 C를 채택한다.

## 5. 최종 사용자 흐름

### 흐름 1. 홈의 최근 경기에서 바로 상세로 이동

1. 사용자는 `/home`에서 `최근 경기 기록 리스트`를 본다.
2. 최근 경기 카드 하나를 누른다.
3. 기록 상세 화면으로 이동한다.
4. 첫 진입 상태는 읽기 전용이다.
5. 날짜/시간은 날짜/시간 영역을 눌러 수정한다.
6. 기록값은 상단 `수정` 버튼을 눌러 수정한다.

### 흐름 2. 더보기에서 전체 경기 목록으로 이동

1. 사용자는 `/home`의 `최근 경기 기록 리스트` 우측에 있는 `더보기`를 누른다.
2. 전체 경기 목록 화면으로 이동한다.
3. 상단의 `연도`, `월` 드롭다운으로 범위를 좁힌다.
4. 목록에서 경기 카드를 누른다.
5. 기록 상세 화면으로 이동한다.
6. 첫 진입 상태는 읽기 전용이다.

### 흐름 3. 상세에서 날짜/시간만 수정

1. 사용자는 기록 상세 화면을 본다.
2. 날짜/시간 영역을 누른다.
3. 날짜/시간 수정 화면으로 이동한다.
4. 날짜와 시간을 수정한다.
5. `저장`을 누르면 기록 상세 화면으로 돌아간다.

### 흐름 4. 상세에서 기록값만 수정

1. 사용자는 기록 상세 화면을 본다.
2. 상단 `수정` 버튼을 누른다.
3. 기록값 수정 화면으로 이동한다.
4. 타석, 사사구, 1루타, 2루타, 3루타, 홈런을 수정한다.
5. `저장`을 누르면 기록 상세 화면으로 돌아간다.

## 6. 화면 구조

### 6-1. 홈 화면

`최근 경기 기록 리스트` 섹션은 아래처럼 동작한다.

- 좌측: 섹션 제목
- 우측: `더보기` 텍스트 버튼
- 본문: 최근 경기 카드 3개

이 `더보기`는 홈 우측 하단의 별도 아이콘을 대체하는 것이 아니라,
최근 경기 섹션 자체의 탐색 진입점이다.
즉 사용자는 최근 경기 섹션 안에서 바로 전체 경기 목록으로 이동할 수 있어야 한다.

최근 경기 카드는 현재 요약형 구성을 유지한다.

- 경기 일시
- 타석
- 안타
- 타율

홈에서는 카드 자체를 무겁게 만들지 않는다.
홈의 역할은 빠른 확인과 빠른 진입이다.

### 6-2. 전체 경기 목록 화면

목록 화면은 "탐색"을 목적으로 한다.

- 상단 제목: `전체 경기 기록`
- 필터: `연도 드롭다운`, `월 드롭다운`
- 본문: 최신순 경기 카드 리스트
- 카드 클릭: 기록 상세 화면 이동

목록 카드의 정보 밀도는 홈 카드와 유사한 수준으로 유지한다.
사용자는 목록에서 빠르게 훑고, 자세한 내용은 상세 화면에서 본다.

### 6-3. 기록 상세 화면

상세 화면은 현재 입력 화면을 거의 재사용한다.
차이는 첫 진입이 읽기 전용이라는 점이다.
즉 "새로운 상세 전용 화면"을 처음부터 따로 설계하기보다,
기존 입력 화면 구조를 읽기 전용 조회 화면으로 재구성하는 방식이다.

표시 정보:

- 입력값
  - 경기 날짜
  - 경기 시간
  - 타석
  - 타수
  - 안타
  - 2루타
  - 3루타
  - 홈런
  - 볼넷
  - 사구
  - 삼진
  - 타점
  - 득점
  - 메모
- 계산값
  - 타율
  - 출루율
  - 장타율
  - OPS

수정 진입:

- 날짜/시간 영역 클릭: 날짜/시간 수정 화면으로 이동
- 상단 `수정` 클릭: 기록값 수정 화면으로 이동

### 6-4. 날짜/시간 수정 화면

날짜/시간 수정은 별도 화면에서 현재 입력 1단계 UI를 재사용한다.
기존 경기의 날짜와 시간이 기본값으로 채워진다.
버튼은 `다음`이 아니라 `저장`을 사용한다.

### 6-5. 기록값 수정 화면

기록값 수정은 별도 화면에서 현재 입력 2단계 UI를 재사용한다.
날짜와 시간은 이 화면에서 보여주지 않는다.
기존 경기 기록 값이 기본값으로 채워진다.
저장 시 기존 경기 기록이 갱신된다.
`삭제`는 이 화면에서 노출하지 않는다.
`삭제`는 기록 상세 화면에서 처리한다.

## 7. 상태

### 읽기 전용 상태

- 모든 입력 항목은 읽기 전용이다.
- 계산값은 별도 강조 영역으로 보여준다.
- 상단에 `수정` 버튼을 둔다.
- 사용자는 카드 클릭 직후 이 상태를 먼저 본다.
- 기록 상세 화면에서는 `삭제`를 노출한다.
- 기록 상세 화면에는 별도 `취소` 또는 `나가기` 버튼을 두지 않는다.
- 날짜/시간 영역을 누르면 날짜/시간만 변경할 수 있다.

### 수정 상태

- 수정은 날짜/시간 수정 화면과 기록값 수정 화면으로 나뉜다.
- 날짜/시간은 별도 화면에서 수정한다.
- 기록값은 별도 기록값 수정 화면에서 수정한다.
- 두 경우 모두 기존 값이 채워진 상태에서 시작한다.
- 저장 시 기존 경기 기록이 갱신된다.
- 저장 후 기록 상세 화면으로 돌아간다.
- `삭제`는 기록 상세 화면에서만 노출한다.

## 8. 왜 카드에서 모든 정보를 다 보여주지 않는가

카드에 모든 정보를 다 넣는 방식도 검토했지만 채택하지 않았다.

이유:

- 리스트 화면에서 카드가 너무 무거워지면 훑기가 어려워진다.
- 기록 수가 늘수록 스크롤 피로가 커진다.
- 수정/삭제까지 고려하면 결국 개별 기록 중심 화면이 필요하다.

따라서 카드의 역할은 "요약과 탐색"으로 제한하고,
상세 화면이 "전체 정보와 액션"을 담당하도록 나눈다.

## 9. 이번 설계의 제품 판단

- 홈은 빠른 진입점이어야 한다.
- 전체 경기 목록은 탐색 허브여야 한다.
- 상세 화면은 입력 화면 재사용 기반의 읽기 전용 시작 화면이어야 한다.
- 날짜/시간은 별도 수정 화면으로 이동한다.
- 기록값은 상단 `수정` 버튼을 통해 Entry Step 2 기반 수정 화면으로 이동한다.
- 삭제는 상세 화면에 두는 것이 가장 명확하다.

## 10. 라우트 관점 정리

이번 설계 기준으로 사용 흐름은 아래처럼 정리한다.

- `/home`
  - 최근 경기 3개 노출
  - `더보기` -> 전체 경기 목록
- `전체 경기 목록 화면`
  - 최신순 리스트
  - 연도/월 드롭다운
  - 카드 클릭 -> 기록 상세
- `기록 상세 화면`
  - 읽기 전용 시작
  - 날짜/시간 영역 클릭 -> 날짜/시간 수정 화면
  - 상단 `수정` 클릭 -> 기록값 수정 화면
  - 삭제 가능
- `날짜/시간 수정 화면`
  - 입력 Step 1 UI 재사용
  - 저장 후 기록 상세 화면으로 복귀
- `기록값 수정 화면`
  - 입력 Step 2 UI 재사용
  - 날짜/시간 미노출

## 11. 후속 구현 범위

이 설계를 구현할 때 다음 순서로 진행한다.

1. 홈 `최근 경기 기록 리스트` 우측 `더보기` 추가
2. 전체 경기 목록 화면 추가
3. 연도/월 드롭다운 필터 추가
4. 기록 상세 화면 추가
5. 읽기 전용 상태 구현
6. 날짜/시간 영역 클릭 기반 별도 수정 화면 구현
7. 상단 `수정` 기반 기록값 수정 화면 구현
8. 기록 상세 화면의 삭제 흐름 구현
