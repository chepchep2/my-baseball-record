# My Baseball Record v1 Screen Design

## 1. Goal

이 문서는 My Baseball Record v1의 실제 화면 구조와
각 화면의 역할, 상태, 전환 규칙을 모바일 웹 기준으로 정의한다.

현재 기준의 v1은 화면 수를 늘리는 대신,
`로그인 → 메인 → 2단계 입력 플로우`를 빠르게 이해하고 사용할 수 있게 만드는 데 집중한다.

## 2. Screen Design Principles

### 1. Mobile Web First

모든 화면은 스마트폰 세로 화면 기준으로 설계한다.
작은 화면에서도 한 번에 무엇을 해야 하는지 바로 이해할 수 있어야 한다.

### 2. No Scroll By Default

핵심 입력 단계는 스크롤 없이 끝나는 것을 우선으로 한다.
단, 현재 구현 기준으로 2단계 입력 화면은 화면 높이에 따라 일부 길어질 수 있다.

### 3. Reduce Input Fatigue

입력은 2단계로 줄인다.
다만 숫자 입력 단계에서는 6개 필드를 모두 보여주되,
사용자는 한 번에 하나의 입력값에만 집중하게 한다.

### 4. Show Progress Clearly

입력 플로우에서는 사용자가 현재 어느 단계에 있는지 항상 알 수 있어야 한다.
현재 구현은 `진행 막대 + 1 / 2` 또는 `2 / 2` 텍스트를 함께 보여준다.

### 5. Respect Native Mobile Back Behavior

안드로이드의 뒤로 가기 버튼, iPhone의 스와이프 백 같은 기본 동작을 무시하지 않는다.
입력 플로우 안에서는 이를 `이전 단계로 이동`하는 행동으로 해석한다.

## 3. Screen List

v1의 핵심 화면은 아래 3개다.

1. 카카오 로그인 화면
2. 메인 화면
3. 경기 기록 입력 플로우

입력 플로우는 하나의 흐름이지만 내부적으로 2단계 화면 상태를 가진다.

## 4. Kakao Login Screen

### Role

- 사용자를 앱 안으로 진입시킨다.
- 카카오 로그인을 통해 인증을 완료하게 한다.
- 로컬 개발 환경에서는 mock 인증으로 바로 홈 화면으로 이동할 수 있다.

### Structure

- 서비스 소개 문구
- 카카오 로그인 버튼
- 로그인 오류 메시지 영역

### Transition

- 로그인 성공 후 홈 화면으로 이동한다.
- 홈에서 기록 0건이면 곧바로 입력 플로우로 리다이렉트된다.

## 5. Main Screen

### Role

- 시즌/통산 핵심 기록을 바로 보여준다.
- 최근 경기 기록을 확인하게 한다.
- 새 기록 입력의 진입점이 된다.

### Structure

- 상단 범위 탭: `올해 시즌 / 통산`
- 핵심 지표 카드
- 최근 경기 기록 리스트
- 우하단 `+` 플로팅 버튼

### Header Metrics

상단 카드에는 아래 8개 지표를 2열 4행으로 보여준다.

- 경기
- 타석
- 타율
- OPS
- 안타
- 사사구
- 출루율
- 장타율

### Recent Games List

최근 경기 기록은 리스트로 보여준다.
리스트 순서는 최근에 입력한 순서가 아니라 실제 경기 시각이 최신인 순서로 노출한다.

- 최대 3개까지만 노출한다.
- 1줄: `월/일 시:분`
- 2줄: `타석 · 안타 · 타율`

리스트 아이템은 현재 구현 기준으로 탭 동작이 없다.
읽기 전용 요약 정보로만 사용한다.

### Main Screen States

- 기록 있음
  - 상단 지표와 최근 경기 리스트를 보여준다.
- 기록 없음
  - 메인 화면보다 입력 플로우를 우선 시작한다.
- 로딩
  - 요약 지표와 최근 경기 영역에 로딩 상태를 보여준다.
- 에러
  - 에러 메시지를 보여준다.

## 6. Entry Flow

### Role

- 사용자가 경기 기록 1건을 빠르게 저장하게 한다.
- 입력 피로를 줄이기 위해 `날짜/시간`과 `기록 입력`을 분리한다.

### Step Structure

입력 플로우는 총 2단계다.

1. 날짜 + 시간
2. 타석 + 사사구 + 1루타 + 2루타 + 3루타 + 홈런 + 저장

### Shared Step Rules

- 각 단계 상단에는 진행 막대와 `현재 단계 / 전체 단계`를 보여준다.
- 숫자 입력은 직접 입력 방식으로 간다.
- 모바일 웹에서는 숫자 키패드를 우선 유도한다.
- 잘못된 값이 있으면 하단 버튼은 비활성화된다.

## 7. Entry Step Design

### Step 1: 날짜 + 시간

#### Role

- 경기 구분의 기준이 되는 날짜와 시각을 받는다.

#### Layout

- 상단 진행 상태: `진행 막대 + 1 / 2`
- 날짜 라벨
- 인라인 달력
- 시간 라벨
- 시간 선택 필드
  - `시`
  - `분`
- 하단 `다음` 버튼

#### Rules

- 날짜는 화면 안에서 인라인 달력으로 바로 선택한다.
- 달력에는 선택한 달의 한 달 전체가 보인다.
- 달력 상단의 연월을 누르면 연도/월 선택이 열린다.
- 오늘 이후 날짜는 선택할 수 없다.
- 미래 날짜는 disabled 상태와 별도 색상으로 보여준다.
- 시간은 드롭다운으로 선택한다.
- 시간은 24시간제를 사용한다.
- `분`은 10분 단위로 선택한다.
- 시간 기본값은 현재 시각 기준이다.
- 현재 시각은 10분 단위로 내림해 기본 선택한다.
- 오늘 날짜를 선택한 경우 미래 시각은 선택할 수 없다.
- 오늘 날짜를 선택한 경우 현재 시를 고르면 미래 분도 선택할 수 없다.

### Step 2: 타자 기록 6개 입력 + 저장

#### Role

- 경기의 타자 기록 6개를 모두 입력받고 저장한다.

#### Layout

- 상단 진행 상태: `진행 막대 + 2 / 2`
- 6개 입력 필드
  - 타석
  - 사사구
  - 1루타
  - 2루타
  - 3루타
  - 홈런
- 오류 메시지 영역
- 하단 액션 버튼

#### Focus Rules

- 6개 입력 필드는 한 화면에 모두 보인다.
- 그러나 한 순간에는 하나의 필드만 활성화된다.
- 활성 필드는 강조한다.
- 비활성 필드는 보이지만 입력할 수 없다.
- 입력 순서는 아래와 같다.
  - 타석
  - 사사구
  - 1루타
  - 2루타
  - 3루타
  - 홈런
- 하단 버튼은 현재 활성 필드가 마지막이 아니면 `다음 항목`으로 동작한다.
- 마지막 필드에서는 하단 버튼이 `저장`으로 동작한다.

## 8. Input And Validation

### Input Rules

- 빈값은 `0`으로 처리한다.
- 모든 입력값은 `0 이상 정수`만 허용한다.
- 음수, 문자, 소수는 허용하지 않는다.

### Validation Timing

- 현재 단계에서 판단 가능한 오류는 즉시 검증한다.
- 잘못된 값이 있으면 오류 메시지를 보여주고 `다음 항목` 또는 `저장` 버튼은 비활성화된다.
- 저장 시점에는 전체 조합을 최종 검증한다.

### Validation Rules

- 타수 = 타석 - 사사구
- 안타 = 1루타 + 2루타 + 3루타 + 홈런
- 타율, 출루율, 장타율, OPS는 자동 계산한다.
- 타석은 사사구보다 작을 수 없다.
- 안타 종류의 합은 타수보다 클 수 없다.

### Error Presentation

- 오류 메시지는 사용자가 이해할 수 있는 문장으로 보여준다.
- 현재 화면에서 확인 가능한 오류는 즉시 노출한다.
- 사용자는 값을 수정한 뒤 바로 같은 화면에서 다시 진행할 수 있어야 한다.

## 9. Back Navigation And Exit Behavior

### Goal

모바일 웹의 기본 뒤로 가기 행동을 거스르지 않으면서,
입력 중인 값을 잃지 않도록 한다.

### Rules

- 입력 플로우의 현재 단계가 `2 / 2`라면 뒤로 가기 시 `1 / 2`로 이동한다.
- 이전 단계로 이동해도 이미 입력한 값은 유지된다.

### First Step Exit

- 현재 단계가 `1 / 2`이고 아직 입력값이 없다면, 뒤로 가기 시 플로우를 종료한다.
- 현재 단계가 `1 / 2`이고 입력값이 하나라도 있다면, 플로우 종료 전에 확인이 필요하다.

### Exit Confirmation

- 첫 단계 이탈 시에는 확인 모달을 보여준다.
- 명시적인 `이전` 또는 `취소` 버튼은 두지 않는다.
- 사용자는 브라우저/OS 기본 뒤로 가기 동작으로만 이전 단계 또는 이탈을 수행한다.
