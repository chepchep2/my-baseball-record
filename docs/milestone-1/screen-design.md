# My Baseball Record v1 Screen Design

## 1. Goal

이 문서는 My Baseball Record v1의 핵심 화면 구조와
각 화면의 역할, 상태, 전환 규칙을 모바일 웹 기준으로 정의한다.

이번 버전은 화면 수를 늘리는 대신,
메인 화면과 입력 플로우를 명확하게 설계하는 데 집중한다.

## 2. Screen Design Principles

### 1. Mobile Web First

모든 화면은 스마트폰 세로 화면 기준으로 설계한다.
작은 화면에서도 한 번에 무엇을 해야 하는지 바로 이해할 수 있어야 한다.

### 2. No Scroll By Default

핵심 입력 단계는 스크롤 없이 끝나야 한다.
한 화면에 너무 많은 정보를 넣지 않는다.

### 3. Reduce Input Fatigue

직접 입력은 최소한으로 제한한다.
6개 값을 한 번에 다 보여주지 않고 단계별로 나눈다.

### 4. Show Progress Clearly

입력 플로우에서는 사용자가 현재 몇 단계에 있는지 항상 알 수 있어야 한다.

### 5. Respect Native Mobile Back Behavior

안드로이드의 뒤로 가기 버튼, iPhone의 스와이프 백 같은 기본 동작을 무시하지 않는다.
입력 플로우 안에서는 이를 `이전 단계로 이동`하는 행동으로 해석한다.

## 3. Screen List

v1의 핵심 화면은 아래 2개로 본다.

1. 카카오 로그인 화면
2. 메인 화면
3. 경기 기록 입력 플로우

입력 플로우는 하나의 흐름이지만 내부적으로 4단계 화면 상태를 가진다.

## 4. Kakao Login Screen

### Role

- 사용자를 앱 안으로 진입시킨다.
- 카카오 로그인을 통해 인증을 완료하게 한다.
- 인증 후 기록 0건 여부에 따라 메인 또는 입력 플로우로 보낸다.

### Structure

- 서비스 소개 문구
- 카카오 로그인 버튼

### Transition

- 로그인 성공 + 기록 0건: 입력 플로우 진입
- 로그인 성공 + 기록 있음: 메인 화면 진입

## 5. Main Screen

### Role

- 시즌/통산 핵심 기록을 바로 보여준다.
- 최근 경기 기록을 확인하게 한다.
- 새 기록 입력의 진입점이 된다.

### Structure

- 상단 범위 탭: `올해 시즌 / 통산`
- 핵심 지표 카드
- 최근 경기 기록 리스트
- 우하단 `+` 플로팅 버튼

### Header Metrics

상단 카드에는 아래 5개 지표를 보여준다.

- 타율
- OPS
- 안타
- 출루율
- 장타율

### Recent Games List

최근 경기 기록은 리스트로 보여준다.

- 최대 2개까지만 노출한다.
- 1줄: `월/일 시:분`
- 2줄: `타석 · 안타 · 타율`

리스트 아이템은 v1에서 탭 동작이 없다.
읽기 전용 요약 정보로만 사용한다.

### Main Screen States

- 기록 있음
  - 상단 지표와 최근 경기 리스트를 보여준다.
- 기록 없음
  - 매번 메인 화면보다 입력 플로우를 우선 시작한다.
- 로딩
  - 요약 지표와 최근 경기 영역에 로딩 상태를 보여준다.
- 에러
  - 다시 시도 가능한 메시지를 보여준다.

## 6. Entry Flow

### Role

- 사용자가 경기 기록 1건을 빠르게 저장하게 한다.
- 입력 피로를 줄이기 위해 단계형으로 진행한다.

### Step Structure

입력 플로우는 총 4단계다.

1. 날짜 + 시간
2. 타석 + 사사구
3. 1루타 + 2루타
4. 3루타 + 홈런 + 저장

### Shared Step Rules

- 각 단계는 스크롤 없이 완료 가능해야 한다.
- 각 단계 상단에는 `현재 단계 / 전체 단계`를 보여준다.
- 각 단계의 핵심 입력은 1개 또는 2개만 둔다.
- 숫자 입력은 직접 입력 방식으로 간다.
- 모바일 웹에서는 숫자 키패드를 우선 유도한다.

## 7. Entry Step Design

### Step 1: 날짜 + 시간

#### Role

- 경기 구분의 기준이 되는 날짜와 시각을 받는다.

#### Layout

- 상단 진행 상태: `1 / 4`
- 날짜 선택 필드
- 시간 선택 필드
  - `시`
  - `분`
- 하단 `다음` 버튼

#### Rules

- 날짜는 선택 필드로 보여주고, 누르면 바텀시트 달력 UI가 열린다.
- 화면 안에 달력을 상시 크게 펼쳐두지 않는다.
- 날짜 기본값은 오늘이다.
- 바텀시트 달력에는 선택한 달의 한 달 전체가 보인다.
- 달력 상단의 연월을 누르면 별도 연월 선택으로 이동할 수 있어야 한다.
- 시간은 드롭다운으로 선택한다.
- 시간은 24시간제를 사용한다.
- `분`은 10분 단위로 선택한다.
- 시간 기본값은 현재 시각 기준이다.
- 현재 시각은 다음 10분 단위로 올림해 기본 선택한다.

### Step 2: 타석 + 사사구

#### Role

- 경기의 기본 타석 정보를 받는다.

#### Layout

- 상단 진행 상태: `2 / 4`
- 가로 2칸 입력
  - 타석
  - 사사구
- 하단 `다음` 버튼

### Step 3: 1루타 + 2루타

#### Role

- 장타를 포함한 안타 종류 일부를 받는다.

#### Layout

- 상단 진행 상태: `3 / 4`
- 가로 2칸 입력
  - 1루타
  - 2루타
- 하단 `다음` 버튼

### Step 4: 3루타 + 홈런 + 저장

#### Role

- 남은 장타 종류를 입력받고 저장을 완료한다.

#### Layout

- 상단 진행 상태: `4 / 4`
- 가로 2칸 입력
  - 3루타
  - 홈런
- 저장 버튼
- 저장 시 검증 오류 메시지 영역

## 8. Input And Validation

### Input Rules

- 빈값은 `0`으로 처리한다.
- 모든 입력값은 `0 이상 정수`만 허용한다.
- 음수, 문자, 소수는 허용하지 않는다.

### Validation Timing

- 현재 단계에서 판단 가능한 오류는 즉시 검증한다.
- 잘못된 값이 있으면 오류 메시지를 보여주고 `다음` 또는 `저장` 버튼은 비활성화된다.
- 저장 시점에는 전체 조합을 최종 검증한다.

### Validation Rules

- 타수 = 타석 - 사사구
- 안타 = 1루타 + 2루타 + 3루타 + 홈런
- 타율, 출루율, 장타율, OPS는 자동 계산한다.
- 타석은 사사구보다 작을 수 없다.
- 안타 종류의 합은 타수보다 클 수 없다.

### Error Presentation

- 오류 메시지는 사용자가 이해할 수 있는 문장으로 보여준다.
- 단계 내에서 확인 가능한 오류는 해당 단계에 즉시 노출한다.
- 저장 시점 최종 오류는 마지막 단계 하단에 노출한다.
- 사용자는 메시지를 보고 값을 수정한 뒤 다시 진행하거나 저장할 수 있어야 한다.

## 9. Back Navigation And Exit Behavior

### Goal

모바일 웹의 기본 뒤로 가기 행동을 거스르지 않으면서,
입력 중인 값을 잃지 않도록 한다.

### Rules

- 안드로이드 뒤로 가기 버튼과 iPhone 스와이프 백은 입력 플로우 안에서 `이전 단계`로 동작한다.
- 현재 단계가 2~4라면 뒤로 가기 시 바로 이전 단계로 이동한다.
- 이전 단계로 이동해도 이미 입력한 값은 유지된다.

### First Step Exit

- 현재 단계가 `1 / 4`이고 아직 입력값이 없다면, 뒤로 가기 시 플로우를 종료한다.
- 현재 단계가 `1 / 4`이고 입력값이 하나라도 있다면, 플로우 종료 전에 확인이 필요하다.

### Exit Confirmation

- 첫 단계 이탈 시에는 확인 모달을 보여준다.
- 명시적인 `이전` 또는 `취소` 버튼은 두지 않는다.
- 사용자는 브라우저/OS 기본 뒤로 가기 동작으로만 이전 단계 또는 이탈을 수행한다.
- 확인 모달 문구는 아래와 같다.
  - 제목: `기록 입력을 중단할까요?`
  - 본문: `지금까지 입력한 내용은 저장되지 않습니다.`
  - 버튼: `계속 입력` / `나가기`

## 10. Entry Flow State Model

입력 플로우는 최소한 아래 상태를 가져야 한다.

- `currentStep`
  - 현재 입력 단계
- `draft`
  - 날짜, 시간, 타석, 사사구, 1루타, 2루타, 3루타, 홈런
- `isDirty`
  - 하나라도 입력했는지 여부
- `validationErrors`
  - 현재 단계 또는 저장 시점 오류

### State Rules

- 단계 이동 중에는 입력값을 유지한다.
- 뒤로 가기 시에도 입력값을 유지한다.
- 별도 임시 저장은 v1에 포함하지 않는다.
- 저장 성공 시 draft와 오류 상태는 초기화한다.
- 저장 성공 후 메인 화면으로 이동한다.

## 11. Primary Transitions

### First-Time User

1. 카카오 로그인
2. 기록 0건 확인
3. 입력 플로우 진입
4. 저장 성공
5. 메인 화면 이동

### Returning User

1. 카카오 로그인
2. 메인 화면 진입
3. `+` 버튼 탭
4. 입력 플로우 진입
5. 저장 성공
6. 메인 화면 갱신
