# PRD

## Product Summary

`마이베이스볼레코드`는 개인 선수 전용 모바일 웹 기록 관리 서비스다.

이 서비스의 목표는 사회인 야구 선수가 여러 곳에 흩어진 자신의 경기 기록을 한곳에 모으고,
시즌과 통산 단위로 계속 관리할 수 있게 만드는 것이다.

v1은 팀 운영 도구가 아니며 리그 관리 도구도 아니다.
제품의 중심은 `기록 확인과 누적 관리`이며, 경기 입력과 경기 관리는 그 가치를 유지시키는 핵심 행동이다.

## Problem

사회인 야구 개인 선수는 공식 기록이 남는 경기와 그렇지 않은 경기를 모두 뛰는 경우가 많다.
하지만 자신의 전체 기록은 게임원, 리그 홈페이지, 개인 메모, 메시지 기록처럼 여러 출처에 흩어져 있다.

이 때문에 사용자는 아래 문제를 겪는다.

- 자신의 시즌 성적을 한 번에 보기 어렵다.
- 통산 기록을 계속 쌓아 관리하기 어렵다.
- 누락 경기와 이미 입력한 경기를 다시 찾아 수정하거나 삭제하기 어렵다.
- 좋은 경기나 시즌 종료 시점에 전체 기록을 다시 확인하려면 직접 계산해야 한다.

## Target User

v1의 대상은 `개인 선수` 한 명이다.

### Included User

- 사회인 야구 선수 개인
- 타자와 투수 모두 포함
- 공식 기록이 있는 경기와 없는 경기를 모두 직접 관리하려는 사람

### Excluded User

- 팀 관리자
- 팀 기록 담당자
- 감독
- 리그 운영자
- 다른 선수 기록을 대신 관리하려는 사용자

## Non-negotiable Product Rules

- 계정 1개는 선수 프로필 1개와 연결된다.
- 사용자는 자신의 기록만 관리한다.
- v1은 팀 또는 다중 선수 프로필 관리 모델을 지원하지 않는다.
- 모든 대표 시나리오와 화면 흐름은 `개인 선수 본인` 시점에서 작성한다.
- Google 계정 1개는 앱 계정 1개와 연결된다.
- 서로 다른 Google 계정은 서로 다른 앱 계정으로 취급한다.
- v1은 계정 연결과 계정 병합을 지원하지 않는다.

## Core Value

사용자는 이 서비스에서 아래 가치를 느껴야 한다.

1. 내 야구 기록이 한곳에 계속 쌓인다.
2. 이번 시즌 성적을 쉽게 확인할 수 있다.
3. 누락 경기와 이미 입력한 경기를 다시 관리할 수 있다.

## Product Positioning

제품의 성격은 아래처럼 정리한다.

- 핵심 문제: 흩어진 기록을 한곳에 모아 시즌 성적을 쉽게 확인하고 관리하기 어렵다.
- 핵심 가치: 내 야구 기록을 계속 모으고 관리할 수 있다.
- 기본 진입 경험: 홈 화면에서 이번 시즌 핵심 지표 확인
- 대표 재방문 순간:
  - 경기 직후 새 경기를 남기고 싶을 때
  - 시즌 중간에 현재 성적이 궁금할 때
  - 시즌이 끝나갈 때 누락 경기와 기존 경기를 정리하고 싶을 때
- 장기 유지 동기:
  - 몇 경기 이상 기록이 쌓인 뒤 시즌 성적이 정리되어 보이는 경험
  - 시즌과 통산 기록이 끊기지 않고 이어진다는 감각

판단이 갈릴 때는 `입력 속도`보다 `기록 관리의 명확성`을 우선한다.

## Usage Context

모바일 웹 사용 맥락은 아래 세 가지를 모두 고려한다.

1. 경기 직후 현장에서 빠르게 기록 입력
2. 시즌 중간에 다시 접속해 현재 성적 확인
3. 나중에 다시 접속해 누락 경기 확인, 수정, 삭제, 시즌 성적 정리

기본 홈은 온보딩 전용 화면이 아니라 `홈 화면`이다.
데이터가 없는 첫 상태에서도 0 지표를 포함한 빈 홈 화면을 보여준다.

## Platform

v1의 목표 플랫폼은 `모바일 웹`이다.

이는 단순히 화면 크기만 줄인 반응형 웹이 아니라,
문서와 설계가 아래 제약을 기본 전제로 가져간다는 의미다.

- 스마트폰 세로 화면 기준으로 핵심 흐름을 먼저 설계한다.
- 작은 화면에서도 기록 확인, 경기 관리, 기록 입력이 모두 가능해야 한다.
- 한 손 사용과 짧은 집중 시간에 대응해야 한다.
- 네트워크 불안정, 화면 이탈, 입력 중단 같은 상황을 고려해야 한다.
- 데스크톱은 모바일 구조를 확장해 보여줄 수는 있지만 별도 핵심 구조를 만들지 않는다.

## Primary Scenarios

v1은 하나의 단일 사용 순간만을 위해 설계하지 않는다.
대표적인 사용 시나리오는 아래 4가지다.

1. 홈 화면에서 이번 시즌 핵심 지표를 빠르게 확인
2. 기록 화면에서 누적 기록을 더 자세히 조회
3. 생성 화면에서 새 경기 기록 입력
4. 경기 화면에서 날짜별 경기 목록을 보고 개별 경기를 수정 또는 삭제

## Information Architecture

v1은 하단 탭바를 중심으로 한 앱형 구조를 사용한다.

- 홈
- 기록
- 생성
- 경기
- 내 정보

각 탭의 역할은 아래와 같다.

- 홈: 현재 시즌 핵심 요약
- 기록: 누적 기록 상세 조회
- 생성: 새 경기 생성 및 기록 입력
- 경기: 캘린더 기반 경기 관리
- 내 정보: 계정 정보와 로그아웃

추가 화면은 아래처럼 연결된다.

- 개별 경기 상세 화면
- 수정 모드 화면
- 삭제 확인 모달

## Scenario Flow

1. 사용자가 서비스를 방문한다.
2. 인증 화면에서 구글 로그인을 진행한다.
3. 로그인 후 홈 화면으로 이동한다.
4. 홈에서 이번 시즌 핵심 지표를 확인한다.
5. 더 많은 누적 지표가 필요하면 기록 탭으로 이동한다.
6. 새 경기 기록을 남기려면 생성 탭으로 이동한다.
7. 날짜별로 입력한 경기를 관리하려면 경기 탭으로 이동한다.
8. 경기 탭에서 오늘 날짜가 기본 선택된 월간 캘린더를 본다.
9. 특정 날짜를 선택하면 그 날짜의 경기 카드 목록이 아래에 보인다.
10. 카드를 누르면 개별 경기 상세 화면으로 이동한다.
11. 더보기 메뉴에서 수정 또는 삭제를 선택한다.
12. 수정은 생성 화면 재사용으로 진행되고, 저장 후 개별 경기 상세 화면으로 돌아온다.
13. 삭제는 확인 모달 후 실행되며, 완료 후 경기 탭으로 돌아온다.

## Locked Rules

- 로그아웃은 `내 정보` 탭에서만 제공한다.
- 하단 탭 순서는 `홈 / 기록 / 생성 / 경기 / 내 정보`로 고정한다.
- 홈은 현재 시즌 핵심 요약만 보여준다.
- 기록은 누적 기록 상세 화면이다.
- 기록 화면의 범위 선택은 `통산`, `현재 시즌`, 과거 시즌을 하나의 드롭다운으로 통합한다.
- 경기 탭은 월간 캘린더가 먼저 보인다.
- 경기 탭은 기본 진입 시 오늘 날짜를 자동 선택한다.
- 캘린더 날짜 셀의 경기 수는 `1`, `2`, `+3` 규칙으로 표시한다.
- 선택한 날짜 아래 목록은 해당 날짜의 경기만 보여준다.
- 경기 카드는 `날짜, 경기 유형, 참여 형태 라벨, 상대 팀`을 표시한다.
- 개별 경기 상세 화면은 저장된 경기 1건의 입력값을 읽기 전용으로 보여주며, 타자/투수는 화면 내 전환으로 나눠서 본다.
- 개별 경기 상세 화면의 수정/삭제는 상단 우측 `더보기` 메뉴 안에 둔다.
- 수정은 생성 화면을 재사용하며 `날짜`와 `경기 유형`은 읽기 전용으로 둔다.
- 수정 완료 후에는 개별 경기 상세 화면으로 돌아간다.
- 삭제는 확인 모달을 거친 뒤 실행한다.
- 삭제 완료 후에는 경기 탭으로 돌아가며, 선택 날짜와 캘린더 수치를 갱신한다.
- 타자 요약/대표 지표는 `경기수, 타수, 총안타, 타율, OPS`로 고정한다.
- 투수 요약/대표 지표는 `경기수, 이닝, ERA, WHIP, 삼진, 승`으로 고정한다.
- 타율과 OPS는 소수 셋째 자리까지 표시한다.
- ERA와 WHIP는 소수 둘째 자리까지 표시한다.
- 투수 이닝 표기는 `0.0 / 0.1 / 0.2` 형식을 사용한다.
- 0분모 비율 지표는 v1에서 `0.000` 또는 `0.00`으로 표기한다.

## Success Criteria

v1 문서는 아래 기준을 만족해야 한다.

- 제품이 개인 선수용 기록 관리 서비스로 명확하게 읽힌다.
- 핵심 가치는 `기록 확인과 누적 관리`로 일관된다.
- 모바일 웹 제약이 상위 문서에 반영된다.
- 경기 입력, 경기 관리, 수정/삭제 흐름이 같은 제품 구조 안에서 이어진다.
- 프론트엔드와 백엔드 구현 계획이 이 범위를 벗어나지 않는다.
