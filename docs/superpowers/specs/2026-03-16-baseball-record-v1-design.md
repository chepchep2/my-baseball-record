# Baseball Record V1 Design

## Goal

사회인 야구 선수 개인이 경기별 타자/투수 요약 기록을 직접 입력하면, 앱이 이를 시즌/통산 기준으로 자동 누적 계산해 통합 기록 화면에서 보여주는 v1을 정의한다.

## Product Direction

v1의 중심 가치는 `빠른 입력` 자체가 아니라 `통합 기록 조회`다.  
사용자는 게임원, 리그 홈페이지, 개인 메모 등 여러 출처에 흩어진 기록을 이 앱에 수동으로 입력하고, 앱은 이를 하나의 시즌/통산 기록으로 자동 계산해 보여준다.

핵심 가치 우선순위는 아래와 같다.

1. 여러 출처 기록을 한 군데로 합쳐 본다.
2. 시즌/통산 기록을 자동 누적으로 본다.
3. 경기 후 기록을 빠르게 입력한다.

## Backend Architecture Direction

백엔드는 DDD에 조금 더 가까운 계층형 구조로 설계한다.  
최상위 기준은 기능보다 레이어를 우선하며, 각 레이어 안에서 `auth`, `game`, `stats` 같은 하위 도메인을 나눈다.

예상 레이어는 아래와 같다.

- `domain`
  - 엔티티, 값 객체, 핵심 규칙
- `application`
  - 유스케이스 조합, 서비스 흐름
- `infrastructure`
  - JPA, 보안, 설정, 외부 구현
- `presentation`
  - Controller, Request/Response DTO

즉 패키지 방향은 `domain.auth`, `application.game`, `infrastructure.security`, `presentation.stats` 같은 구조를 기본으로 한다.

## Primary User

- 사회인 야구 선수 개인
- 타자와 투수 모두 포함
- 게임원 등 공식 기록을 쓰는 사람과 직접 기록하는 사람 모두 포함

## Persona

리그 경기와 비공식 경기를 비슷한 비중으로 뛰는 사회인 야구 선수 개인으로, 기록을 개인 보관과 추억의 관점에서 중요하게 여기고 실력 확인의 수단으로도 활용한다. 현재는 게임원과 리그 홈페이지 등 여러 곳에 흩어진 기록을 확인하지만, 시즌 종료 시점이나 좋은 경기 직후 자신의 전체 성적을 한 번에 보고 싶을 때마다 누적 기록을 직접 다시 계산해야 하는 점을 가장 큰 불편으로 느낀다.

## Primary Scenario

시즌 종료 시점에 자신의 전체 성적이 궁금해진 사용자는 먼저 게임원과 리그 홈페이지 등 기존 기록 출처를 확인한 뒤, 서비스에 자신이 먼저 정리하고 싶은 경기 기록부터 하나씩 입력한다. 입력을 마치면 통합 기록 화면에서 이번 시즌 성적을 가장 먼저 확인하고, 여러 출처에 흩어져 있던 기록이 한 번에 합쳐져 보인다는 점에서 가장 큰 가치를 느낀다.

### Scenario Flow

1. 시즌 종료 시점에 자신의 전체 성적이 궁금해진 사용자가 서비스를 방문한다.
2. 인증 화면에서 회원가입 또는 로그인을 진행한다.
3. 로그인 후 기본 진입 화면인 `이번 시즌 기록 화면`에 들어간다.
4. 입력된 기록이 없거나 부족하더라도, 화면에는 0을 포함한 기본 통계 카드 구조가 먼저 보인다.
5. 사용자는 상단의 `경기 추가` 버튼을 눌러 경기 생성 및 기록 입력 흐름으로 이동한다.
6. 경기 정보를 입력하고, 타자 기록과 투수 기록 중 필요한 내용을 입력한다.
7. 저장 후 다시 `이번 시즌 기록 화면`으로 돌아온다.
8. 사용자는 이번 시즌 통합 성적이 반영된 화면을 확인하고, 여러 출처에 흩어진 기록이 한 번에 합쳐져 보인다는 점에서 가장 큰 가치를 느낀다.

## Core User Flow

1. 사용자가 로그인한다.
2. 사용자가 경기를 생성한다.
3. 같은 경기 안에서 타자 기록과 투수 기록을 각각 선택적으로 입력한다.
4. 앱이 입력된 기록을 현재 시즌과 통산 기록에 자동 반영한다.
5. 사용자는 `이번 시즌`을 기본 진입점으로 통합 기록 화면을 본다.
6. 필요하면 `통산` 또는 특정 연도를 선택해 기록을 전환해서 본다.

## Information Architecture

### Main Axes

- 시간 축: `통산 / 연도별 시즌`
- 기록 축: `타자 / 투수`
- 보기 탭: `통합`
- 필터: `전체 / 리그 / 비공식 경기`

### Default Entry

- 기본 진입은 `이번 시즌`
- 사용자가 `타자 / 투수`를 직접 전환
- `통합` 탭을 기본으로 둔다
- 필터 기본값은 `전체`

## Authentication

v1은 이메일/비밀번호 + access token / refresh token 기반 인증을 사용한다.  
모든 경기와 기록 데이터는 로그인한 사용자 개인 소유로 분리 관리한다.

### Included In V1

- 회원가입
- 로그인
- 로그아웃
- 토큰 재발급

### Logout Direction

- 로그아웃은 단순 클라이언트 토큰 삭제가 아니라 refresh token 무효화를 포함한다.
- 즉 v1에서도 실제 세션 종료에 가까운 로그아웃을 목표로 한다.

### Future Direction

- 향후 구글, 카카오 등 소셜 로그인 추가를 고려한다.
- 내부 구조는 나중에 이메일 계정과 소셜 계정을 연결할 수 있도록 확장 가능성을 열어둔다.

## Data Model

### Game

경기 공통 정보는 별도 엔티티로 저장한다.

v1에서는 `Game`을 로그인한 사용자의 개인 경기 기록 단위로 본다.  
즉 하나의 실제 경기를 여러 사용자가 공유하는 모델이 아니라, 사용자가 자신의 기록 관리를 위해 소유하는 경기 객체다.

장기적으로 팀 경기, 용병 공동 참여, 다중 사용자 연결이 필요해지면 `실제 경기`와 `사용자별 참여 기록`을 분리하는 방향으로 확장할 수 있다.

- 날짜
- 시즌/연도
  - 기본은 날짜 기준 자동 설정
  - 필요 시 수동 수정 가능
- 경기 유형
  - 리그
  - 비공식 경기
- 소속 팀
- 상대 팀
- 메모

### Batter Record

한 경기 안에서 선택적으로 입력 가능하다.

#### Basic Input

- 타석
- 타수
- 1루타
- 2루타
- 3루타
- 홈런
- 볼넷
- 삼진
- 사구

#### Additional Input

- 타점
- 득점
- 도루
- 도루자
- 희생타

#### Calculated Values

- 총안타
- 타율
- 출루율
- 장타율
- OPS

참고:
- `안타`는 총안타와 혼동될 수 있으므로 직접 입력값으로 받지 않는다.
- 총안타는 `1루타 + 2루타 + 3루타 + 홈런`으로 계산한다.

### Pitcher Record

한 경기 안에서 선택적으로 입력 가능하다.

#### Basic Input

- 이닝
  - 정수 이닝
  - 추가 아웃 수 (`0`, `1`, `2`)
- 실점
- 자책
- 피안타
- 볼넷
- 삼진

#### Additional Input

- 사구
- 피홈런
- 상대한 타자 수
- 승
- 패
- 세이브
- 홀드

#### Calculated Values

- ERA
- WHIP
- 피안타율
- 탈삼진율

참고:
- 사용자 입력은 야구식 이닝 표기를 그대로 쓰지 않고 `정수 이닝 + 추가 아웃 수`로 받는다.
- 예: `4이닝 0아웃`, `3이닝 2아웃`
- 내부 저장은 계산 안정성을 위해 `outsRecorded` 정수로 변환한다.
- 예: `4이닝 0아웃 -> 12`, `3이닝 2아웃 -> 11`

## Input Design

v1의 입력 단위는 `경기 단위 요약 입력`이다.  
타석별 로그, 이닝별 로그, pitch-by-pitch 입력은 제외한다.

### Input Flow

1. 경기 생성
2. 타자 기록 입력 여부 선택
3. 투수 기록 입력 여부 선택
4. 저장
5. 시즌/통산 자동 반영

### UX Principles

- 입력은 수동 입력만 지원
- 모든 경기를 앱 내부 데이터로 누적 계산
- 기본 항목을 우선 노출하고 추가 항목은 펼쳐서 입력
- 한 경기에서 타자와 투수 기록을 둘 다 입력 가능

## V1 Scope

### Included

- 로그인/회원가입
- 로그아웃
- access token / refresh token 기반 인증
- 경기 생성
- 타자/투수 경기 요약 기록 입력
- 한 경기에서 타자/투수 기록 동시 입력
- 시즌/통산 자동 누적 계산
- 타자/투수 전환 화면
- 통합 기록 화면
- 전체/리그/비공식 경기 필터
- 날짜 기반 시즌 자동 설정 및 수동 수정

### Excluded

- 게임원/외부 사이트 자동 연동
- 타석별 상세 로그 입력
- 이닝별 상세 로그 입력
- 최근 경기 조회
- 팀별 필터
- 공유 카드
- 커뮤니티 기능
- 리그 운영 기능
- 영상 업로드/편집 기능

## Key Decisions

- v1의 핵심 가치는 `통합 조회`다.
- 입력은 모두 수동이다.
- 인증은 이메일/비밀번호 기반으로 시작한다.
- 인증은 access token / refresh token 구조로 간다.
- 경기 유형과 시즌 구분은 조회를 위한 핵심 메타데이터다.
- 필터 기본값은 `전체`다.
- v1에서는 용병, 친선, 연습 경기를 `비공식 경기` 한 타입으로 묶는다.
- 시즌 화면이 기본이며, 통산/연도별 조회는 보조 전환으로 제공한다.
- 로그인/회원가입은 첫 구현 범위에 포함한다.
- 기록과 경기 데이터는 사용자별로 분리 관리한다.
- 소셜 로그인은 후속 버전에서 추가할 수 있도록 확장 가능성을 고려한다.
