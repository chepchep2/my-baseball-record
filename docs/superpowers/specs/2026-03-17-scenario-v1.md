# Baseball Record V1 User Scenarios

> **작성일**: 2026-03-17
> **제품**: My Baseball Record
> **유형**: 개인 선수 전용 모바일 웹 기록 관리 서비스

## Why This Document Exists

이 문서는 기능 목록을 다시 적는 문서가 아니다.
`어떤 사용자가 어떤 순간에 이 앱을 열고, 어디서 가치를 느끼고, 왜 계속 쓰게 되는가`를 사람 중심으로 정리하는 시나리오 문서다.

이번 버전의 공통 구조는 아래를 전제로 한다.

- 하단 탭: `홈 / 기록 / 생성 / 경기 / 내 정보`
- 홈: 현재 시즌 핵심 요약
- 기록: 누적 기록 상세
- 생성: 새 경기 입력
- 경기: 캘린더 기반 경기 관리
- 내 정보: 계정 정보와 로그아웃

## Scenario 1: 시즌 중반의 확인 욕구

### 프로필

**김민준**, 31세, 직장인  
주말마다 리그 경기와 친선 경기를 둘 다 뛴다.

### 순간

6월 중순, 시즌 성적이 궁금해져 앱을 연다.

### 흐름

1. Google 로그인 후 홈 화면으로 들어간다.
2. 홈에서 현재 시즌 핵심 지표를 본다.
3. 더 자세한 누적 기록이 궁금해 기록 탭으로 이동한다.
4. 시즌/통산, 타자/투수, 경기 유형을 조정하며 상세 지표를 본다.

### Peak Moment

`흩어진 기록이 시즌 기록으로 하나로 보이는 순간`

## Scenario 2: 좋은 경기 직후의 기록 보존 욕구

### 프로필

**박지훈**, 28세, 회사원  
잘한 경기는 꼭 남기고 싶어 한다.

### 순간

토요일 경기 직후, 4타수 3안타 1홈런 경기였다.

### 흐름

1. 앱을 열고 홈에서 `생성` 탭으로 이동한다.
2. 경기 정보 입력 후 타자 기록을 남긴다.
3. 저장 후 개별 경기 상세로 이동해 방금 저장한 내용을 확인한다.
4. 이후 홈 탭으로 돌아와 시즌 기록에 반영된 결과를 본다.

### Peak Moment

`방금 경기의 기록이 시즌 기록에 바로 붙는 순간`

## Scenario 3: 시즌 마감의 전체 정리 욕구

### 프로필

**최성호**, 35세, 직장인  
주로 투수로 뛰고, 시즌 끝에 전체 기록을 꼭 정리한다.

### 순간

11월 초, 누락된 경기들을 며칠에 걸쳐 입력하고 정리하고 싶다.

### 흐름

1. 홈에서 현재 시즌 상태를 확인한다.
2. 생성 탭으로 들어가 누락 경기를 하나씩 입력한다.
3. 기록 탭에서 ERA, WHIP, 이닝, 삼진 등 누적 지표를 다시 본다.

### Peak Moment

`리그 경기와 비공식 경기를 합친 자기 시즌이 완성되어 보이는 순간`

## Scenario 4: 잘못 입력한 경기 수정 욕구

### 프로필

**이정훈**, 33세, 직장인  
경기 직후 급하게 입력하다 보면 숫자를 잘못 넣는 일이 있다.

### 순간

어제 입력한 경기의 타수와 안타 수 일부가 잘못된 것 같다.

### 흐름

1. 하단 탭에서 `경기`로 이동한다.
2. 월간 캘린더에서 어제 날짜를 누른다.
3. 아래 경기 카드 목록에서 해당 경기를 찾는다.
4. 카드를 눌러 개별 경기 상세 화면으로 들어간다.
5. `더보기 -> 수정`을 누른다.
6. 수정 모드에서 기존 값이 채워진 화면을 보고 숫자를 고친다.
7. 저장 후 다시 개별 경기 상세 화면으로 돌아와 수정 결과를 확인한다.

### Peak Moment

`입력한 기록을 다시 찾고, 고치고, 바로 확인할 수 있는 순간`

## Input Modes

v1의 경기 입력은 한 가지 방식만 가정하지 않는다.
아래 세 가지 입력 방식이 모두 가능해야 한다.

- 시합 중 점진 입력
- 시합 끝난 당일 입력
- 며칠 뒤 정리 입력

## Scenario 6: 시합 중 점진 입력

### 프로필

**정우성**, 30세, 사회인 야구 선수  
경기 직후 한 번에 다 적기보다, 경기 중간중간 결과를 조금씩 기록하는 편이 더 편하다고 느낀다.

### 순간

경기 시작 전, 생성 탭에서 날짜와 경기 유형을 먼저 입력한다.
타자/투수 기록은 아직 다 채우지 않는다.

### 흐름

1. 생성 탭으로 들어간다.
2. 날짜와 경기 유형을 입력한다.
3. 기록 입력 단계로 이동한다.
4. 첫 타석이 끝난 뒤 `1타석, 1타수, 1루타` 같은 값을 입력한다.
5. 화면을 끄거나 다른 앱으로 이동한다.
6. 다시 생성 화면으로 돌아오면 같은 세션 안에서는 입력값이 자동으로 복구된다.
7. 다음 타석이나 이닝이 끝날 때마다 값을 이어서 입력한다.
8. 경기 종료 후 최종 저장을 누른다.

### Peak Moment

`경기 중간에 끊겨도 이어서 입력할 수 있다는 안도감`

## Non-happy-path Scenarios

### Scenario 7: 잘못된 숫자 입력 후 저장 실패

#### 순간

사용자가 타석보다 많은 타수를 입력하거나, 실점보다 큰 자책점을 입력한다.

#### 흐름

1. 생성 탭에서 경기 정보를 입력한다.
2. 기록 입력 단계에서 잘못된 숫자를 입력한다.
3. 저장을 누른다.
4. 앱은 저장을 막고 어떤 필드가 왜 잘못됐는지 보여준다.
5. 사용자는 값을 수정한다.
6. 다시 저장하고 성공한다.

#### 핵심 의미

비정상 입력이 들어와도 사용자가 무엇을 고쳐야 하는지 이해할 수 있어야 한다.

### Scenario 8: 중복 경기 입력 후 삭제

#### 순간

사용자가 같은 날짜에 비슷한 경기를 두 번 입력한 것을 나중에 발견한다.

#### 흐름

1. 경기 탭에서 날짜를 선택한다.
2. 동일 날짜의 경기 카드가 두 개 보이는 것을 확인한다.
3. 중복된 경기 카드를 눌러 개별 경기 상세 화면으로 이동한다.
4. `더보기 -> 삭제`를 선택한다.
5. 확인 모달에서 삭제를 확정한다.
6. 경기 탭으로 돌아와 목록과 캘린더 수치가 갱신된 것을 본다.

#### 핵심 의미

경기 관리 탭은 단순 보기 화면이 아니라 잘못 입력한 기록을 정리하는 기준점이어야 한다.

### Scenario 9: 입력 중 이탈과 복구

#### 순간

사용자가 경기 입력 또는 수정 중에 다른 탭으로 이동하거나, 브라우저를 닫고 나중에 다시 돌아온다.

#### 흐름

1. 생성 또는 수정 화면에서 일부 값을 입력한다.
2. 입력값이 바뀔 때마다 localStorage에 임시 저장된다.
3. 같은 세션 안에서 다른 탭으로 이동했다가 돌아오면 값이 자동 복구된다.
4. 브라우저를 다시 열어 생성/수정 화면에 진입하면 복구 확인 모달이 뜬다.
5. `예`를 누르면 이어서 작성하고, `아니오`를 누르면 임시 저장을 지우고 새로 시작한다.
6. 최종 저장이 완료되면 임시 저장은 삭제된다.

#### 핵심 의미

이탈은 무조건 실패가 아니라, 사용자가 입력을 이어갈 수 있는 상태로 설계돼야 한다.

## Product Interpretation

이 시나리오들을 같이 보면 v1은 단순 입력 앱이 아니다.

- 홈은 현재 시즌 감각을 주는 화면이다.
- 기록은 누적 기록을 깊게 보는 화면이다.
- 생성은 새 경기를 남기는 화면이다.
- 경기는 날짜 기준으로 기록을 관리하는 화면이다.
- 개별 경기 상세는 수정/삭제의 기준점이다.

즉 v1은 `입력 -> 누적 -> 관리`가 하나로 이어지는 개인 기록 관리 서비스다.
