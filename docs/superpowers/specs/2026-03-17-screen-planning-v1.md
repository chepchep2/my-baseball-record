# Baseball Record V1 Screen Planning

## Goal

Baseball Record v1의 핵심 화면 구조와 각 화면의 목적, 입력 요소, 상태, 전환 흐름을
모바일 웹 기준으로 정의한다.

이 문서는 시각 디자인 문서가 아니라 화면 기획 문서다.
즉 `예쁘게 어떻게 보일까`보다
`어떤 화면이 왜 필요하고, 어떤 정보와 행동이 있어야 하는가`를 먼저 고정하는 데 목적이 있다.

## Screen Groups

v1의 핵심 화면군은 아래 8개로 정의한다.

1. 인증 화면
2. 홈 화면
3. 기록 화면
4. 생성 화면
5. 경기 화면
6. 개별 경기 상세 화면
7. 내 정보 화면
8. 삭제 확인 모달

수정 모드 화면은 생성 화면 재사용으로 다룬다.

## Screen Planning Principles

### 1. Record View First

기본 홈은 `홈 화면`이다.
첫 진입 시에도 설명 전용 온보딩 화면으로 대체하지 않는다.

### 2. Empty State Still Uses Real Structure

기록이 하나도 없어도 0 지표를 포함한 기록 화면 구조를 먼저 보여준다.
즉 빈 상태도 기록 관리 제품의 얼굴을 유지해야 한다.

### 3. Mobile Web First

모든 화면은 스마트폰 세로 화면 기준으로 기획한다.
데스크톱은 모바일 구조를 확장해 보여줄 수 있지만,
핵심 액션과 핵심 정보구조는 모바일 기준을 따른다.

### 4. Management Must Stay Practical

사용자는 새 경기 입력뿐 아니라,
이미 입력한 경기를 날짜별로 다시 찾고 수정하거나 삭제할 수 있어야 한다.
따라서 `경기` 탭과 `개별 경기 상세` 화면은 v1 핵심 화면군에 포함된다.

### 5. Input Must Remain Practical

타자/투수의 기본 기록 항목은 모두 입력 가능해야 한다.
모바일 사용성은 항목 축소보다 단계 분리, 상태 유지, 숫자 입력 최적화로 해결한다.

## Shared Mobile Layout Rules

- 하단 탭바를 전역 이동의 기본 수단으로 사용한다.
- 하단 탭 순서는 `홈 / 기록 / 생성 / 경기 / 내 정보`로 고정한다.
- 홈, 기록, 생성, 경기, 내 정보, 개별 경기 상세 화면에서는 하단 탭바를 보여준다.
- 수정 모드에서는 입력 집중을 위해 하단 탭바를 숨긴다.
- 상단 영역은 화면 제목과 현재 컨텍스트를 보여주는 데 집중한다.
- 핵심 액션은 작은 화면에서 쉽게 접근 가능해야 하며 헤더 과밀을 만들지 않는다.
- 필터와 전환 UI는 한 줄 고정 배치보다 모바일 스택 구조를 우선한다.

## Shared State Rules

모든 화면은 정상 상태만 다루지 않는다.
화면 기획에는 아래 상태를 포함한다.

- 빈 상태
- 로딩 상태
- 에러 상태
- 저장 중 상태
- 저장 실패 상태
- 인증 만료 상태
- 이탈 확인 상태
- 삭제 확인 상태

---

## 1. 인증 화면

### 목적

- 사용자를 서비스 안으로 진입시킨다.
- 구글 로그인을 통해 인증을 완료하게 한다.
- 인증 성공 후 홈 화면으로 보낸다.

### 구조

- 단일 인증 화면에서 구글 로그인 버튼을 제공한다.
- 이메일/비밀번호 입력 폼은 두지 않는다.

### 주요 액션

- 구글 로그인

### 성공 결과

- 구글 인증 성공 시 백엔드가 앱 세션을 발급하고 홈 화면으로 이동한다.

### 에러 처리

- 구글 인증 실패: 상단 메시지 표시
- 인증 취소: 상단 메시지 표시
- 앱 세션 만료: 상단 메시지 표시

---

## 2. 홈 화면

### 목적

- 현재 시즌 핵심 지표를 가장 빠르게 보여준다.
- 이 서비스의 핵심 가치를 가장 직접적으로 보여주는 기본 홈 화면이다.

### 기본 진입 상태

- 기본 범위: 이번 시즌
- 기본 홈: 기록이 없더라도 홈 화면

### 첫 화면 우선순위

1. 이번 시즌 핵심 지표 요약
2. 하단 탭을 통한 전역 이동

### 상단 구조

- 브랜드
- 화면 제목
- 현재 시즌 컨텍스트

### 화면 내 전환 요소

- 타자
- 투수

### 정보 구조

1. 현재 시즌 제목
2. 핵심 지표 요약

### 빈 상태

- 0 지표 구조 유지
- 기록이 없다는 안내

### 타자 핵심 지표

- 경기수
- 타수
- 총안타
- 타율
- OPS

### 투수 핵심 지표

- 경기수
- 이닝
- ERA
- WHIP
- 삼진
- 승

---

## 3. 기록 화면

### 목적

- 누적 기록을 더 자세히 조회한다.
- 범위, 경기 유형, 타자/투수 기준으로 상세 기록을 확인하게 한다.

### 진입 방식

- 하단 탭 `기록`

### 상단 구조

- 화면 제목

### 화면 내 전환 요소

#### 범위 선택

- 기본값은 현재 시즌
- 선택지는 `통산`, `2026 시즌`, `2025 시즌`, `2024 시즌`처럼 구성한다
- `시즌 / 통산` 버튼과 연도 선택은 하나의 드롭다운으로 통합한다

#### 기록 축 전환

- 타자
- 투수

#### 경기 유형 필터

- 전체 경기
- 리그 경기
- 비공식 경기

### 정보 구조

1. 범위 선택과 경기 유형 선택
2. 기록 축 전환
3. 대표 지표 요약 블록
4. 상세 지표 목록

모바일에서는 아래 두 줄 구성을 기본으로 둔다.

- 첫 줄: `범위 선택` + `경기 유형 선택`
- 둘째 줄: `타자 / 투수`

상세 지표 목록은 가능한 경우 `한 줄에 두 항목씩` 짝을 맞춰 스캔하기 쉽게 구성한다.

### 타자 대표 지표

- 경기수
- 타수
- 총안타
- 타율
- OPS

### 투수 대표 지표

- 경기수
- 이닝
- ERA
- WHIP
- 삼진
- 승

## 4. 생성 화면

### 목적

- 사용자가 새 경기 하나를 만들고
- 같은 경기 안에서 타자 기록과 투수 기록을 선택적으로 입력하게 한다.

### 전체 흐름

1. 경기 정보 입력
2. 기록 입력
3. 저장
4. 개별 경기 상세로 이동

이 화면은 아래 세 가지 입력 방식을 모두 지원해야 한다.

- 경기 중 점진 입력
- 경기 끝난 당일 입력
- 며칠 뒤 정리 입력

### 단계 구조

- 1단계: 경기 정보
- 2단계: 기록 입력

기록 입력 단계 안에서도 모든 필드를 한 번에 같은 무게로 노출하지 않는다.
모바일에서는 `한 번에 한 구성`에 집중하게 하는 구조를 우선한다.

### 경기 정보 입력 단계

#### 필수 입력값

- 날짜
- 경기 유형

#### 선택 입력값

- 시즌/연도
  - 날짜 기준 자동 계산
- 소속 팀
- 상대 팀
- 메모

#### 정책

- 날짜는 오늘 이후를 선택할 수 없게 제한한다.
- 날짜 변경 시 시즌 값은 자동 동기화한다.
- `선택 정보 더 입력하기`를 통해 optional 필드를 펼친다.
- 경기 정보를 먼저 만들고 기록 입력 단계로 넘어간 뒤, 경기 중간중간 값을 이어서 입력할 수 있다.

### 기록 입력 단계

#### 구조

- `타자 기록 / 투수 기록` 전환형
- 각 탭은 `구성` 단위로 나뉜다
- 한 번에 한 구성만 노출한다
- 첫 구성에서는 `다음 구성`만 보여준다
- 마지막 구성에서는 `이전 구성`만 보여준다

#### 타자 구성

- 기본 구성
  - 타석
  - 타수
  - 1루타
  - 2루타
  - 3루타
  - 홈런
- 추가 구성
  - 볼넷
  - 삼진
  - 사구
  - 타점
  - 득점
  - 도루
  - 도루자
  - 희생타

#### 저장 정책

- 타자만 입력하고 저장 가능
- 투수만 입력하고 저장 가능
- 둘 다 입력하고 저장 가능

#### 임시 저장 정책

- 생성 화면과 수정 화면 모두 임시 저장을 지원한다.
- 입력값 변경 시 localStorage에 자동 저장한다.
- 같은 세션 안에서 다시 들어오면 자동 복구한다.
- 브라우저 재진입 후 생성/수정 화면에 들어오면 복구 확인 모달을 띄운다.
- 모달 문구는 `이전에 작성 중이던 경기 기록이 있습니다. 이어쓰겠습니까?`를 기본으로 한다.
- `예`를 누르면 복구하고, `아니오`를 누르면 임시 저장을 삭제하고 새로 시작한다.
- 최종 저장 완료 시 임시 저장은 삭제한다.
- 경기 중 점진 입력의 중간값은 서버에 부분 저장하지 않고 localStorage에만 유지한다.

## 5. 경기 화면

### 목적

- 캘린더 기준으로 입력한 경기를 관리한다.
- 날짜별 경기 목록을 보고 개별 경기 상세로 진입하게 한다.

### 기본 진입 상태

- 월간 캘린더 먼저 표시
- 오늘 날짜 자동 선택

### 캘린더 규칙

- 캘린더는 라이브러리를 사용한다.
- 날짜 셀에는 경기 수를 표시한다.
  - 1경기: `1`
  - 2경기: `2`
  - 3경기 이상: `+3`

### 목록 규칙

- 캘린더 아래 목록은 선택한 날짜의 경기만 보여준다.
- 선택 날짜에 경기가 없으면 아래 문구만 보여준다.
  - `이 날짜에 기록된 경기가 없습니다.`
- 빈 상태에서 별도 생성 버튼은 두지 않는다.

### 경기 카드

- 날짜
- 경기 유형
- 참여 형태 라벨
  - 타자
  - 투수
  - 타자+투수
- 상대 팀

### 카드 행동

- 카드를 누르면 개별 경기 상세 화면으로 이동한다.
- 카드 안에 수정/삭제 버튼은 두지 않는다.

---

## 6. 개별 경기 상세 화면

### 목적

- 저장된 경기 1건의 전체 입력값을 읽기 전용으로 보여준다.
- 수정/삭제의 진입점이 된다.

### 구조

- 경기 기본 정보
- `타자 / 투수` 전환
- 현재 선택된 기록 축의 상세 값
- 하단 탭바 유지

### 액션

- 상단 우측 `더보기`
  - 수정
  - 삭제

### 수정 흐름

- 생성 화면을 재사용한다.
- 기존 값이 미리 채워진다.
- 날짜와 경기 유형은 읽기 전용이다.
- 저장 후 개별 경기 상세 화면으로 돌아온다.

### 삭제 흐름

- 더보기에서 삭제 선택
- 삭제 확인 모달 표시
- 삭제 완료 후 경기 탭으로 돌아간다.
- 돌아갈 때 선택 날짜와 캘린더 수치를 갱신한다.

## 7. 내 정보 화면

### 목적

- 최소 계정 정보를 제공한다.
- 로그아웃 진입점을 제공한다.

### 기본 정보

- 로그인 방식

### 주요 액션

- 로그아웃

---

## 8. 삭제 확인 모달

### 목적

- 경기 삭제를 바로 실행하지 않고 한 번 더 확인한다.

### 문구 방향

- 정말 삭제할지 묻는다.
- 삭제 후 복구되지 않는다는 점을 안내한다.

### 주요 액션

- 취소
- 삭제
