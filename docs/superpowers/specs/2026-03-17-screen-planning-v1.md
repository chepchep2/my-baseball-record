# Baseball Record V1 Screen Planning

## Goal

Baseball Record v1의 핵심 화면 구조와 각 화면의 목적, 입력 요소, 상태, 전환 흐름을 정의한다.

이 문서는 시각 디자인 문서가 아니라 화면 기획 문서다.  
즉 "예쁘게 어떻게 보일까"보다 "어떤 화면이 왜 필요하고, 어떤 정보와 행동이 있어야 하는가"를 먼저 고정하는 데 목적이 있다.

## Screen Groups

v1 화면군은 아래 3개로 정의한다.

1. 인증 화면
2. 경기 생성 및 기록 입력 화면
3. 기록 확인 화면

최근 경기 화면은 현재 단계에서 메인 화면군으로 분리하지 않고, 후속 검토 대상으로 둔다.

## Persona Context

대표 사용자는 리그 경기와 비공식 경기를 비슷한 비중으로 뛰는 사회인 야구 선수 개인이다.  
기록을 개인 보관과 추억의 관점에서 중요하게 여기며, 실력 확인의 수단으로도 활용한다.  
현재는 게임원과 리그 홈페이지 등 여러 출처에 흩어진 기록을 확인하지만, 시즌 종료 시점이나 좋은 경기 직후 자신의 전체 성적을 한 번에 보고 싶을 때마다 누적 기록을 직접 다시 계산해야 하는 점을 가장 큰 불편으로 느낀다.

## Primary Scenario Context

시즌 종료 시점에 자신의 전체 성적이 궁금해진 사용자는 먼저 게임원과 리그 홈페이지 등 기존 기록 출처를 확인한 뒤, 서비스에 자신이 먼저 정리하고 싶은 경기 기록부터 하나씩 입력한다. 입력을 마치면 통합 기록 화면에서 이번 시즌 성적을 가장 먼저 확인하고, 여러 출처에 흩어져 있던 기록이 한 번에 합쳐져 보인다는 점에서 가장 큰 가치를 느낀다.

## 1. 인증 화면

### 목적

- 사용자를 서비스 안으로 진입시킨다.
- 회원가입과 로그인을 하나의 화면군 안에서 자연스럽게 전환하게 한다.
- 인증 성공 후 기록 확인 화면으로 보낸다.

### 구조

- 하나의 인증 화면군 안에서 `로그인` / `회원가입` 탭 전환
- 기본 진입 탭은 추후 결정 가능하지만, 일반적으로 `로그인`을 기본으로 둘 수 있다

### 로그인 화면

#### 목적

- 기존 사용자가 이메일과 비밀번호로 로그인한다.

#### 필수 입력값

- 이메일
- 비밀번호

#### 주요 액션

- 로그인 버튼
- 회원가입 탭으로 전환

#### 성공 결과

- 로그인 성공 시 기록 확인 화면으로 이동한다.

#### 에러 처리

- 이메일 형식 오류: 해당 필드 아래 표시
- 비밀번호 누락: 해당 필드 아래 표시
- 이메일 또는 비밀번호 불일치: 화면 상단 메시지 표시
- 인증 만료 또는 토큰 문제: 화면 상단 메시지 표시

### 회원가입 화면

#### 목적

- 신규 사용자가 계정을 만든다.

#### 필수 입력값

- 이름
- 이메일
- 비밀번호
- 비밀번호 확인

#### 입력 정책

- 이름은 실명 입력을 원칙으로 한다.
- 단, v1에서는 본인인증 기반 실명 검증은 하지 않는다.
- 비밀번호 규칙은 `최소 8자 + 영문 + 숫자 + 특수문자 포함`이다.

#### 주요 액션

- 회원가입 버튼
- 로그인 탭으로 전환

#### 성공 결과

- 회원가입 성공 시 자동 로그인 처리한다.
- 자동 로그인 후 기록 확인 화면으로 이동한다.

#### 에러 처리

- 이름 미입력: 필드 아래 표시
- 이메일 형식 오류: 필드 아래 표시
- 이미 가입된 이메일: 화면 상단 메시지 표시
- 비밀번호 규칙 불충족: 필드 아래 표시
- 비밀번호 확인 불일치: 필드 아래 표시

### 로그아웃

#### 위치

- 기록 확인 화면 상단 우측 메뉴 안에 둔다.

#### 정책

- 로그아웃은 단순 클라이언트 토큰 삭제가 아니라 refresh token 무효화를 포함한다.
- access token / refresh token 구조를 전제로 한다.

## 2. 경기 생성 및 기록 입력 화면

### 목적

- 사용자가 경기 하나를 만들고,
- 같은 경기 안에서 타자 기록과 투수 기록을 선택적으로 입력하게 한다.

### 전체 흐름

1. 경기 정보 입력
2. 타자 기록 입력
3. 다음
4. 투수 기록 입력
5. 저장
6. 기록 확인 화면으로 이동

중요:

- 타자만 입력 가능
- 투수만 입력 가능
- 둘 다 입력 가능

즉 한 경기에서 두 기록 모두 지원하되, 실제 사용자는 필요한 쪽만 입력할 수 있어야 한다.

### 2-1. 경기 정보 입력 단계

#### 목적

- 경기 메타데이터를 먼저 만든다.

#### 필수 입력값

- 날짜
- 경기 유형

#### 선택 입력값

- 시즌/연도
  - 날짜 기준 자동 계산
  - 필요 시 사용자가 수정 가능
- 소속 팀
- 상대 팀
- 메모

#### 경기 유형

- 리그
- 비공식 경기

#### 정책

- 상대 팀은 비공식 경기에서 모르거나 중요하지 않을 수 있으므로 nullable 허용
- 소속 팀도 nullable 허용
- 메모는 보조 정보이므로 선택 입력

#### 주요 액션

- 다음 버튼

#### 검증

- 날짜 미입력 시 에러
- 경기 유형 미선택 시 에러

### 2-2. 기록 입력 단계

#### 구조

- `타자 탭` / `투수 탭` 전환형
- 접기/펼치기 섹션형은 사용하지 않음

#### 기본 원칙

- 각 탭은 `기본 항목`을 먼저 보여준다
- `추가 기록 입력` 버튼으로 추가 항목을 펼친다

#### 저장 정책

- 타자 탭만 입력하고 저장 가능
- 투수 탭만 입력하고 저장 가능
- 둘 다 입력하고 저장 가능
- 한 탭이 완전히 비어 있으면 미입력으로 간주
- 한 탭에서 한 개라도 값을 입력했다면 유효한 기록 세트인지 검증한다

#### 에러 처리 정책

- 잘못된 필드는 해당 필드 아래에 에러 표시
- 저장 불가 사유는 탭 상단에 요약 메시지 표시

### 2-3. 타자 기록 입력 탭

#### 기본 항목

- 타석
- 타수
- 1루타
- 2루타
- 3루타
- 홈런
- 볼넷
- 삼진
- 사구

#### 추가 항목

- 타점
- 득점
- 도루
- 도루자
- 희생타

### 2-4. 투수 기록 입력 탭

#### 기본 항목

- 정수 이닝
- 추가 아웃 수 (`0`, `1`, `2`)
- 실점
- 자책
- 피안타
- 볼넷
- 삼진

#### 추가 항목

- 사구
- 피홈런
- 상대한 타자 수
- 승
- 패
- 세이브
- 홀드

#### 입력 정책

- 사용자는 `정수 이닝 + 추가 아웃 수`로 입력한다
- 예: `4이닝 0아웃`, `3이닝 2아웃`
- 내부 저장은 `outsRecorded`로 변환한다

#### 검증

- `추가 아웃 수`는 `0`, `1`, `2`만 허용
- 하나라도 값을 입력했다면 필요한 필드 검증 수행

### 저장 후 이동

- 기본 흐름은 저장 후 기록 확인 화면으로 이동

## 3. 기록 확인 화면

### 목적

- 흩어진 기록을 한 번에 합쳐 시즌/통산 성적을 확인하게 한다.
- 이 서비스의 핵심 가치를 가장 직접적으로 보여주는 메인 화면이다.

### 기본 진입 상태

- 기본 연도: 이번 시즌
- 기본 기록 타입: 타자
- 기본 보기: 통합 기록

### 상단 구조

#### 기록 타입 전환

- 타자
- 투수

#### 연도 선택

- 드롭다운 형태
- 예: `통산 / 2026 / 2025 ...`

#### 경기 유형 필터

- 세그먼트 형태
- `전체 | 리그 | 비공식 경기`

### 메인 내용

#### 기본 방향

- 최근 경기보다 `통합 기록` 중심
- `최근 경기`는 현재 단계에서 메인 설계 우선순위에서 제외

#### 정보 구조

1. 핵심 지표를 카드형으로 먼저 노출
2. 상세 지표는 아래 영역에서 제공

### 3-1. 타자 통합 기록 화면

#### 핵심 지표 카드

- 경기수
- 타석
- 타수
- 총안타
- 홈런
- 타점
- 타율
- 출루율
- 장타율
- OPS

#### 상세 지표

- 1루타
- 2루타
- 3루타
- 볼넷
- 사구
- 도루
- 도루자
- 희생타
- 득점

### 3-2. 투수 통합 기록 화면

#### 핵심 지표 카드

- 경기수
- 이닝
- 승
- 패
- 세이브
- 홀드
- ERA
- WHIP
- 삼진

#### 상세 지표

- 자책
- 실점
- 피안타
- 피홈런
- 볼넷
- 사구
- 상대한 타자 수
- 피안타율
- 탈삼진율

### 로그아웃 접근

- 화면 상단 우측 메뉴 안에 로그아웃 배치
