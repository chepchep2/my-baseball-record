# Baseball Record V1 Screen Planning

## Goal

Baseball Record v1의 핵심 화면 구조와 각 화면의 목적, 입력 요소, 상태, 전환 흐름을
모바일 웹 기준으로 정의한다.

이 문서는 시각 디자인 문서가 아니라 화면 기획 문서다.
즉 `예쁘게 어떻게 보일까`보다
`어떤 화면이 왜 필요하고, 어떤 정보와 행동이 있어야 하는가`를 먼저 고정하는 데 목적이 있다.

## Screen Groups

v1의 핵심 화면군은 아래 5개로 정의한다.

1. 인증 화면
2. 기록 확인 요약 화면
3. 내 정보 화면
4. 상세 기록 화면
5. 경기 생성 및 기록 입력 화면

최근 경기 전용 화면은 현재 단계에서 메인 화면군으로 분리하지 않는다.

## Screen Planning Principles

### 1. Record View First

기본 홈은 `기록 확인 요약 화면`이다.
첫 진입 시에도 설명 전용 온보딩 화면으로 대체하지 않는다.

### 2. Empty State Still Uses Real Structure

기록이 하나도 없어도 0 지표를 포함한 기록 화면 구조를 먼저 보여준다.
즉 빈 상태도 기록 관리 제품의 얼굴을 유지해야 한다.

### 2-1. Three Scenarios Must Fit The Same Screens

화면군은 아래 3가지 사용 순간을 모두 자연스럽게 지원해야 한다.

- 시즌 중간 점검
- 경기 직후 입력
- 시즌 마감 정리

따라서 화면 기획은 당일 경기 입력만 잘 되는 구조로 좁아지면 안 된다.
기록 확인 요약 화면은 `현재 성적 확인`, `새 경기 추가`, `누락 경기 정리`의 출발점이 모두 되어야 한다.

### 3. Mobile Web First

모든 화면은 스마트폰 세로 화면 기준으로 기획한다.
데스크톱은 모바일 구조를 확장해 보여줄 수 있지만,
핵심 액션과 핵심 정보구조는 모바일 기준을 따른다.

### 4. Clarity Over Input Speed

입력 속도보다 기록 관리의 명확성을 우선한다.
따라서 홈 화면은 입력 유도보다 기록 요약을 먼저 보여주고,
입력 화면은 필드 수를 줄이는 대신 단계와 상태를 명확히 한다.

### 5. Input Must Remain Practical

타자/투수의 기본 기록 항목은 모두 입력 가능해야 한다.
모바일 사용성은 항목 축소보다 단계 분리, 상태 유지, 숫자 입력 최적화로 해결한다.

## Shared Mobile Layout Rules

- 상단 영역은 화면 제목과 현재 컨텍스트를 보여주는 데 집중한다.
- 핵심 행동은 작은 화면에서 쉽게 접근 가능해야 하며, 헤더 과밀을 만들지 않는다.
- 필터와 전환 UI는 한 줄 고정 배치보다 모바일 스택 구조를 우선한다.
- 기록 화면의 첫 화면은 `이번 시즌 핵심 지표 요약`이 먼저 보이도록 구성한다.
- 요약 화면은 핵심 지표 확인에 집중하고, 상세 지표는 별도 상세 기록 화면에서 깊게 제공한다.
- 입력 화면은 단계형 구조를 유지한다.
- 단계 전환과 탭 전환 시 값은 유지된다.
- 입력 중 이탈 시 경고를 제공한다.

## Shared State Rules

모든 화면은 정상 상태만 다루지 않는다.
화면 기획에는 아래 상태를 포함한다.

- 빈 상태
- 로딩 상태
- 에러 상태
- 저장 중 상태
- 저장 실패 상태
- 인증 만료 상태
- 이탈 확인 상태

## 1. 인증 화면

### 목적

- 사용자를 서비스 안으로 진입시킨다.
- 구글 로그인을 통해 인증을 완료하게 한다.
- 인증 성공 후 기록 확인 요약 화면으로 보낸다.

### 구조

- 단일 인증 화면에서 구글 로그인 버튼을 제공한다.
- 이메일/비밀번호 입력 폼은 두지 않는다.

### 인증 화면

#### 목적

- 사용자가 구글 계정으로 인증한다.

#### 주요 액션

- 구글 로그인

#### 성공 결과

- 구글 인증 성공 시 백엔드가 앱 세션을 발급하고, 기록 확인 요약 화면으로 이동한다.

#### 에러 처리

- 구글 인증 실패: 상단 메시지 표시
- 인증 취소: 상단 메시지 표시
- 앱 세션 만료: 상단 메시지 표시
- 세션 갱신 실패: 상단 메시지 표시

#### 모바일 입력 규칙

- 외부 인증 화면으로 이동하더라도 복귀 흐름이 자연스러워야 한다.
- 인증 복귀 후 현재 세션 상태가 분명히 반영되어야 한다.

### 로그아웃

#### 위치

- 기록 확인 요약 화면의 1차 행동으로 두지 않는다.
- 기록 확인 요약 화면을 아래로 내렸을 때 보이는 저강도 하단 영역에 둔다.

#### 정책

- 로그아웃은 단순 클라이언트 토큰 삭제가 아니라 refresh token 무효화를 포함한다.
- access token / refresh token 구조를 전제로 한다.

## 2. 기록 확인 요약 화면

### 목적

- 흩어진 기록이 한곳에 쌓이고 있다는 감각을 가장 빠르게 보여준다.
- 이 서비스의 핵심 가치를 가장 직접적으로 보여주는 기본 홈 화면이다.
- 모바일에서 첫 진입 시 가장 먼저 보는 기록 요약 화면이다.

### 기본 진입 상태

- 기본 범위: 이번 시즌
- 기본 경기 유형 필터: 전체
- 기본 홈: 기록이 없더라도 기록 확인 요약 화면

### 첫 화면 우선순위

1. 이번 시즌 핵심 지표 요약
2. 경기 추가 행동
3. 상세 기록 화면 진입 행동
4. 현재 범위와 필터 맥락

### 상단 구조

상단 영역은 아래 요소를 다룬다.

- 화면 제목
- 현재 보고 있는 범위 정보
- 주요 액션

상단 영역은 작은 화면에서 과밀해지지 않아야 하며,
핵심 액션과 필터를 모두 한 줄에 억지로 넣지 않는다.
저빈도 보조 행동은 헤더에 고정하지 않는다.

### 화면 내 전환 요소

#### 기록 축 전환

- 타자
- 투수

#### 모바일 우선순위

- `기록 축 전환`은 화면 안에서 바로 보이는 1순위 전환 요소다.
- `범위`와 `경기 유형`은 요약 화면에서 직접 모두 조작하기보다,
  현재 선택값을 요약해서 보여주고 상세 기록 화면에서 조정할 수 있다.
- `로그아웃`은 주 행동과 분리된 상단 프로필 메뉴 안에 둔다.
- 프로필 메뉴에는 `내 정보`, `로그아웃`이 포함된다.

### 내 정보 화면

#### 목적

- 프로필 메뉴에서 진입하는 최소 계정 화면을 제공한다.
- v1에서는 계정 확장 기능보다 현재 로그인 정보를 단순하게 보여주는 데 집중한다.

#### 기본 정보

- 로그인 방식

#### 주요 액션

- 뒤로

### 메인 정보 구조

1. 이번 시즌 또는 현재 범위 컨텍스트
2. 핵심 지표 요약
3. 경기 추가 행동
4. `기록 보기` 또는 `상세 기록` 진입 행동
5. 필요 시 다시 입력을 이어갈 수 있는 맥락

#### 핵심 지표 요약 원칙

- 모바일 첫 화면에서도 핵심 가치가 충분히 느껴지도록 5개 안팎의 지표를 바로 보여줄 수 있다.
- 다만 필터와 보조 행동을 줄여서 핵심 지표가 먼저 읽히게 해야 한다.
- 상세 지표 전체를 첫 화면에 길게 노출하기보다, 별도 상세 기록 화면에서 충분히 제공한다.

### 빈 상태

기록이 없어도 아래 구조를 유지한다.

- 0 지표 기반 핵심 요약
- 기록이 아직 없다는 안내
- `경기 추가` 행동
- `상세 기록` 진입 행동은 있어도 되지만, 핵심은 경기 추가 유도다

즉 빈 상태는 `아무것도 없는 화면`이 아니라
`여기서부터 기록을 쌓아가는 화면`이어야 한다.

### 2-1. 타자 기록 요약 화면

#### 핵심 지표

- 경기수
- 타수
- 총안타
- 타율
- OPS

### 2-2. 투수 기록 요약 화면

#### 핵심 지표

- 경기수
- 이닝
- ERA
- WHIP
- 삼진
- 승

### 상태

#### 빈 상태

- 0 지표 구조 유지
- 기록이 없다는 안내
- 경기 추가 유도

#### 조회 실패 상태

- 조회 실패 전용 단순 상태 화면처럼 노출할 수 있다.
- 현재 기록을 불러오지 못했다는 메시지
- 다시 시도 행동 제공

#### 인증 만료 상태

- 기존 기록 화면 필터를 모두 유지하지 않아도 된다.
- 세션 만료 전용 상태 화면처럼 단순하게 노출할 수 있다.
- 앱 세션이 만료되었음을 안내
- 세션 갱신 또는 재로그인 흐름으로 연결

#### 로그아웃 접근

- 기록 확인 요약 화면 상단의 프로필 메뉴에서 접근 가능해야 한다.

#### 로딩 상태

- 현재 기록을 불러오는 중임을 표시한다.
- 가능한 한 기존 화면 구조를 유지한 채 로딩 상태를 보여준다.

#### 시즌 정리 진행 상태

- 누락 경기들을 나눠 입력하는 사용자를 고려한다.
- 저장 후 기록 확인 요약 화면으로 돌아왔을 때 다시 `경기 추가`를 이어가기 쉬워야 한다.
- 화면은 현재 시즌이 계속 채워지고 있다는 감각을 해치지 않아야 한다.
- 별도 독립 화면보다는 기존 기록 확인 요약 화면 안의 짧은 상태 문구 또는 행동 제안으로 다룬다.

## 4. 상세 기록 화면

### 목적

- 요약 화면보다 더 많은 지표와 필터를 제공한다.
- 사용자가 시즌/통산, 시즌 선택, 경기 유형, 타자/투수 기준으로 상세 기록을 확인하게 한다.
- 모바일에서 `자주 보는 요약`과 `깊게 보는 기록`을 분리해 첫 화면 피로를 줄인다.
- 저장된 개별 경기 하나를 다시 여는 화면이 아니라, 누적 기록을 더 깊게 보는 화면이다.

### 진입 방식

- 기록 확인 요약 화면의 `기록 보기` 또는 `상세 기록` 행동으로 진입

### 상단 구조

- 화면 제목
- 현재 선택된 범위 요약

### 화면 내 전환 요소

#### 범위 전환

- 시즌
- 통산

#### 시즌 선택

- 시즌 범위일 때만 노출

#### 기록 축 전환

- 타자
- 투수

#### 경기 유형 필터

- 전체 경기
- 리그 경기
- 비공식 경기

### 정보 구조

1. 범위 전환과 시즌 선택
2. 기록 축 전환과 경기 유형 선택
2. 대표 지표 요약 블록
3. 상세 지표 목록
4. 하단 뒤로 행동

모바일에서는 아래 두 줄 구성을 기본으로 둔다.

- 첫 줄: `시즌 / 통산` + `시즌 선택`
- 둘째 줄: `타자 / 투수` + `경기 유형 선택`

상세 지표 목록은 모바일에서 한 줄에 하나씩 길게 나열하기보다,
가능한 경우 `한 줄에 두 항목씩` 짝을 맞춰 스캔하기 쉽게 구성한다.
단, 의미상 단독으로 보여야 하는 항목은 한 줄 전체를 사용한다.

## 5. 경기 생성 및 기록 입력 화면

### 목적

- 사용자가 경기 하나를 만들고
- 같은 경기 안에서 타자 기록과 투수 기록을 선택적으로 입력하게 한다.

### 전체 흐름

1. 경기 정보 입력
2. 기록 입력
3. 저장
4. 기록 확인 요약 화면으로 이동

중요한 점은 아래와 같다.

- 타자만 입력 가능
- 투수만 입력 가능
- 둘 다 입력 가능

즉 한 경기에서 두 기록 모두 지원하되,
실제 사용자는 필요한 쪽만 입력할 수 있어야 한다.

저장 후 기본 복귀 화면은 기록 확인 요약 화면이지만,
시즌 마감 정리처럼 여러 경기를 연속 입력하는 사용자를 위해
다시 `경기 추가`로 이어지기 쉬운 흐름을 함께 고려해야 한다.

### 단계 구조

기록 입력 화면은 단일 긴 폼보다 단계형 구조를 우선한다.

- 1단계: 경기 정보
- 2단계: 기록 입력

`다음` 이전에는 기록 입력 단계가 핵심 입력 영역으로 노출되지 않는다.
즉 경기 정보 단계와 기록 입력 단계는 역할이 분명히 나뉘어야 한다.

기록 입력 단계 안에서도 모든 필드를 한 번에 같은 무게로 노출하지 않는다.
모바일에서는 `한 번에 한 필드`보다 `한 번에 한 입력 묶음`에 집중하게 하는 구조를 우선한다.
따라서 현재 묶음만 노출하고, `이전 구성 / 다음 구성`으로 이동하는 흐름을 기본으로 둔다.

### 3-1. 경기 정보 입력 단계

#### 목적

- 경기 메타데이터를 먼저 만든다.

#### 필수 입력값

- 날짜
- 경기 유형

#### 선택 입력값

- 시즌/연도
  - 날짜 기준 자동 계산
  - 현재 프로토타입에서는 날짜 변경 시 자동 동기화
- 소속 팀
- 상대 팀
- 메모

#### 경기 유형

- 리그
- 비공식 경기

#### 정책

- 상대 팀은 비공식 경기에서 모르거나 중요하지 않을 수 있으므로 nullable 허용
- 소속 팀도 nullable 허용
- 메모는 선택 입력
- `날짜`, `경기 유형`을 가장 먼저 보여주고
  `시즌/연도`, `소속 팀`, `상대 팀`, `메모`는 뒤쪽 또는 접기 가능한 선택 영역으로 둘 수 있다

#### 주요 액션

- 다음
- 취소 또는 이탈

#### 액션 배치

- 하단 고정 액션 영역에 `취소`와 `다음`을 둔다
- `다음`은 주 행동, `취소`는 전체 입력 중단 행동이다
- `취소`를 누르면 이번 경기 입력 전체를 중단하는 의미임을 분명히 안내한다

#### 검증

- 날짜 미입력 시 에러
- 경기 유형 미선택 시 에러

#### 모바일 입력 규칙

- 날짜는 모바일에 적합한 날짜 선택 방식을 사용한다.
- 날짜는 오늘 이후를 선택할 수 없게 제한한다.
- 숫자 중심 필드는 숫자 입력 흐름을 방해하지 않아야 한다.

### 3-2. 기록 입력 단계

#### 구조

- `타자 기록 / 투수 기록` 전환형
- 각 탭은 `구성` 단위로 나뉜다
- 한 번에 한 구성만 노출한다
- `이전 구성 / 다음 구성`으로 이동한다
- 마지막 구성에서는 `다음 구성`을 숨기고, 첫 구성에서는 `이전 구성`을 숨긴다

#### 저장 정책

- 타자 탭만 입력하고 저장 가능
- 투수 탭만 입력하고 저장 가능
- 둘 다 입력하고 저장 가능
- 한 탭이 완전히 비어 있으면 미입력으로 간주
- 한 탭에서 한 개라도 값을 입력했다면 유효한 기록 세트인지 검증한다

#### 상태 유지 정책

- 타자/투수 탭 전환 시 값 유지
- 단계 전환 시 값 유지
- 저장 실패 후 재시도 시 값 유지
- `뒤로`는 경기 정보 단계로 돌아가되 입력값을 유지한다

#### 에러 처리 정책

- 잘못된 필드는 해당 필드 아래에 에러 표시
- 저장 불가 사유는 단계 상단에 요약 메시지 표시

#### 액션 배치

- 하단 고정 액션 영역에 `뒤로`와 `저장`을 둔다
- `저장`은 현재 입력값으로 경기를 저장하는 주 행동이다
- `뒤로`는 이전 단계 이동을 위한 보조 행동이며 값은 유지된다
- 저장 성공 직후에는 `다음 경기 계속 추가` 행동을 함께 제안할 수 있다

### 3-3. 타자 기록 입력 탭

#### 기본 항목

- 타석
- 타수
- 1루타
- 2루타
- 3루타
- 홈런

#### 추가 항목

- 볼넷
- 삼진
- 사구
- 타점
- 득점
- 도루
- 도루자
- 희생타

#### 검증 방향

- 일부라도 값을 입력했다면 유효한 타자 기록 세트인지 검사
- 잘못된 필드는 필드 아래에 에러 표시

### 3-4. 투수 기록 입력 탭

#### 기본 항목

- 이닝
- 추가 아웃 수 (`0`, `1`, `2`)
- 실점
- 자책
- 피안타
- 볼넷
- 삼진

#### 추가 항목

- 사구
- 피홈런
- 상대한 타자 수
- 승
- 패
- 세이브
- 홀드

#### 입력 정책

- 사용자는 `이닝 + 추가 아웃 수`로 입력한다
- 내부 저장은 `outsRecorded`로 변환한다

#### 검증 방향

- `추가 아웃 수`는 `0`, `1`, `2`만 허용
- 일부라도 값을 입력했다면 유효한 투수 기록 세트인지 검사

### 저장 후 이동

- 저장 성공 시 기록 확인 요약 화면으로 이동
- 저장 성공 후 방금 입력한 결과가 반영된 현재 범위를 다시 보여줌

### 이탈 정책

- 입력값이 존재하는 상태에서 이탈하려 하면 경고를 제공한다
- 세션 안에서는 단계와 탭을 옮겨도 값이 유지된다
- 완전한 로컬 드래프트 복구는 v1 필수 범위에 포함하지 않는다

### 상태

#### 저장 중

- 중복 저장 방지
- 저장 중 상태 표시

#### 저장 실패

- 실패 메시지 표시
- 재시도 가능
- 기존 입력값 유지
- 저장 실패 상태는 입력 탭을 다시 보여주기보다 `입력으로 돌아가기`와 `다시 시도` 중심으로 단순하게 보여줄 수 있다.

#### 인증 만료

- 앱 세션 만료 안내
- 세션 갱신 실패 시 재로그인 후 다시 흐름을 이어갈 수 있게 설계
